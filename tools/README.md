# tools/headless.ts — 헤드리스 대량 시뮬레이션 CLI

브라우저 없이 전투 시뮬레이션과 육성 루프를 돌려 밸런싱 수치를 뽑는 도구입니다.
`src/core/**` 만 사용하며 DOM 을 건드리지 않습니다. 외부 라이브러리 의존성은 없고
`tsx` 로 바로 실행합니다.

```
npm run headless -- [옵션]
```

`npm run headless` 뒤의 `--` 는 npm 이 옵션을 스크립트에 넘기도록 하는 구분자입니다. 빠뜨리면 옵션이 무시됩니다.

## 옵션

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `--games N` | 100 | 시뮬레이션할 판 수 |
| `--seed S` | 1 | 루트 시드. 같은 시드 + 같은 옵션이면 결과가 완전히 같음 |
| `--map M` | random | `plains` / `dark` / `desert` / `glacier` / `random`. random 이면 판마다 시드에서 파생해 선택 |
| `--cycle C` | 5 | 양 팀을 `generateOpponentTeam` 으로 만들 때의 육성 사이클 (1~10). 1 은 갓 뽑은 팀, 10 은 완성 팀 수준 |
| `--determinism` | – | 같은 입력으로 전투를 두 번 돌려 틱마다 프레임 해시를 비교 |
| `--growth` | – | 10사이클 육성을 자동 정책으로 끝까지 진행하고 분화 보장을 검증 |
| `--json` | – | 표 대신 요약 JSON 을 stdout 에 출력 (다른 도구에 넘기기 좋음) |
| `--help` | – | 도움말 |

`--games=200` 처럼 `=` 로 붙여 써도 됩니다.

## 1. 대량 전투 (기본 모드)

```
npm run headless -- --games 200 --seed 1
npm run headless -- --games 500 --map desert --cycle 10
npm run headless -- --games 1000 --json > result.json
```

판마다 `hashSeed("시드:판번호:A")`, `...:B`, `...:battle`, `...:map` 으로 시드를 파생하므로
판 수를 늘려도 앞쪽 판의 입력은 바뀌지 않습니다 (`--games 100` 의 1~100판 = `--games 200` 의 1~100판).

출력 표:

- **전체 결과**: A 승 / B 승 / 무승부 비율, 평균 전투 시간(초).
  두 팀 모두 같은 방식으로 생성되므로 A 와 B 승률이 크게 다르면 스폰 위치나 진영 처리에 편향이 있다는 뜻입니다.
- **맵별 A 승률**: 맵별 판수, A/B/무승부 비율, 평균 시간.
- **직업별**: 메인 직업마다 등장 횟수(캐릭터 단위), 승률(그 직업이 포함된 팀이 이긴 비율), 무승부 비율,
  평균 피해량, 평균 회복량, 생존율, 평균 킬, 평균 스킬 사용 횟수. 승률 내림차순.
  소환물의 피해·회복·킬은 `summon` 이벤트의 소환사에게 합산됩니다.
- **스킬 사용 상위 10**: `skill` 이벤트 기준 사용 횟수와 판당 횟수.
- **종료 사유**: `annihilation` / `timeout_hp` / `capture` / `timeout_draw` 등의 히스토그램.

20판 이상이면 진행률을 stderr 에 표시합니다 (`--json` 일 때는 표시하지 않음).

## 2. 결정론 검증

```
npm run headless -- --determinism --seed 3 --map glacier --cycle 8
```

`--seed`/`--map`/`--cycle` 로 만든 0번 판의 입력을 JSON 으로 두 번 복사해 시뮬레이터 두 개를 만들고,
틱마다 `step()` 결과(유닛 스냅샷, 이벤트, 거점 상태, 종료 플래그)를 직렬화한 FNV-1a 해시를 비교합니다.

- **프레임 해시 비교**: 첫 불일치 틱과 어느 유닛의 어느 필드가 달랐는지 출력.
- **최종 결과 비교**: `result()` 직렬화 비교.
- **입력 불변 검사**: 시뮬레이터가 `BattleInput` 객체를 수정했는지 검사 (경고만, PASS/FAIL 판정에는 포함하지 않음).

모두 통과하면 `결과: PASS`, 종료 코드 0. 실패 시 종료 코드 1 이므로 CI 에서 쓸 수 있습니다.

## 3. 육성 헤드리스

```
npm run headless -- --growth --seed 1
npm run headless -- --growth --seed 42 --json
```

`src/core/growth/run.ts` 상태 머신을 다음 단순 정책으로 끝까지 진행합니다.

1. 풀에서 앞에서부터 서로 다른 메인 직업 5명을 고른다.
2. 전투는 `runToEnd()` 로 즉시 끝낸다.
3. 보너스 단계에서는 팀 전체 후보 중 가장 싼 스킬을 살 수 있을 때까지 계속 산다.
4. 로그라이크 선택은 항상 0번 선택지를 고른다.

출력:

- **사이클별 진행**: 맵, 승/패/무, 종료 사유, 전투 시간, 획득 보너스, 구매한 스킬 수, 선택 후 팀 평균 스탯 합, 고른 선택지 제목(도박형은 성공/실패 표시).
- **직업 분화 보장 검증**: 캐릭터마다 예정 사이클(`subJobChoiceCycle`), 분화 선택지가 실제로 등장한 (사이클:선택 순번), 최종 세부 직업, 판정.
  판정 기준은 "분화 선택지가 등장한 사이클이 정확히 하나이고 그 사이클이 4~6 사이" 입니다.
  같은 사이클 안에서 여러 번 등장하는 것(0번 선택지를 고르느라 분화를 놓친 뒤 다시 제시되는 경우)은 1회로 셉니다.
  최종 세부 직업이 비어 있어도 판정에는 영향이 없습니다. 정책이 분화 선택지를 고르지 않았을 수 있기 때문입니다.

모든 캐릭터가 PASS 이고 10사이클이 `done` 까지 도달하면 종료 코드 0, 아니면 1.

## 종료 코드

| 코드 | 의미 |
|---|---|
| 0 | 정상 (검증 모드는 PASS) |
| 1 | `--determinism` 또는 `--growth` 검증 실패 |
| 2 | 잘못된 옵션 |

## 시드 파생 규칙

전부 `src/core/rng.ts` 의 `Rng` 와 `hashSeed` 만 사용합니다. `Math.random`, `Date` 는 쓰지 않습니다.

| 용도 | 시드 |
|---|---|
| 판 g 의 맵 (`--map random`) | `hashSeed("S:g:map")` |
| 판 g 의 팀 A / B | `hashSeed("S:g:A")` / `hashSeed("S:g:B")` |
| 판 g 의 전투 | `hashSeed("S:g:battle")` |
| 육성 모드 | `newRun(S)` 이후는 run.ts 가 `hashSeed("S:cycle:step")` 로 파생 |

## 활용 팁

- 직업 밸런스: `--games 1000 --cycle 10` 으로 완성 팀 기준 승률 표를 보고, 승률이 50% 에서 크게 벗어나는 직업의 `statProfile`/스킬 계수를 조정합니다.
- 맵 밸런스: `--map` 을 바꿔가며 종료 사유 분포를 봅니다. 사막에서 `timeout_hp` 가 대부분이면 제한시간이 짧거나 피해량이 낮은 것입니다.
- 시뮬레이터를 고친 뒤에는 항상 `--determinism` 을 한 번 돌려 순회 순서나 부동소수점 문제로 결정론이 깨지지 않았는지 확인합니다.
- 결과를 비교할 때는 `--json` 출력을 파일로 저장해 두고 diff 하는 것이 편합니다.
