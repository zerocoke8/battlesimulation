# tools/headless.ts — 헤드리스 대량 시뮬레이션 / 밸런싱 CLI (v0.6)

브라우저 없이 전투 시뮬레이션과 육성 루프(10일 × 5스텝)를 돌려 밸런싱 수치를 뽑는 도구입니다.
`src/core/**` 만 사용하며 DOM 을 건드리지 않습니다. 외부 라이브러리 의존성은 없고 `tsx` 로 바로 실행합니다.

```
npm run headless -- [옵션]
```

`npm run headless` 뒤의 `--` 는 npm 이 옵션을 스크립트에 넘기도록 하는 구분자입니다. 빠뜨리면 옵션이 무시됩니다.

하루 구성(고정): **1선택 · 2선택 · 3몬스터 · 4선택 · 5전투** → 하루 마무리(`day_end`) → 다음 날. 총 10일.

v0.6 에서 바뀐 것 (설계 사양 [3] 스킬 위력 상향 측정):

- `--games` 에 **스킬 피해 비중 / 기본 공격 비중** 표와 **주력기 1회 피해 / 대상 최대 HP** 표를 추가했습니다 (7절).
- **`--skills`** 모드를 새로 만들었습니다. `--games N` 판을 돌려 같은 표를 스킬별 전체 목록(사용·평균 1회 피해 %·전체 비중, 비중 내림차순)으로 뽑고,
  **직업별 기본 풀(분화 전)에 광역 피해 스킬이 있는지**(설계 [2]) 와 **마법사 시작 스킬 후보가 전부 광역인지**(설계 [1]) 를 PASS/FAIL 로 검사합니다.
- sim 이 프레임 이벤트에 피해 출처를 실어 줍니다: `attack.skillId`(스킬 피해면 있음), `zone_damage`(장판 틱), `dot`(화상·중독 틱), `reflect`(반사).
  도구는 그것을 그대로 더합니다 (7.1절). 추정 규칙은 없습니다.

v0.5 에서 바뀐 것:

- 팀 인원 상수화. 기준 팀·상대팀은 `TEAM_SIZE`(4) 명, 몬스터는 `MONSTER_TEAM_MIN`~`MONSTER_TEAM_MAX`(1~8) 명. 도구 안에 5 나 4 를 숫자로 박은 곳은 없습니다. 표기는 전부 `4:4`.
- 광역 예고(텔레그래프)·회피·장판 도입에 맞춰 **광역 영역(Zone)·회피 통계**를 `--games` / `--growth` 에 추가하고, 회피 공식과 실전 회피율을 측정하는 **`--dodge`** 모드를 새로 만들었습니다.
- `--monster` 에 편성 **인원** 열과 **인원 구간(1~2 / 3~4 / 5~8) 승률표**를 추가했습니다 (1기 보스와 8기 떼의 편차 ±8%p 목표).
- `--determinism` 의 프레임 해시에 `zones` 가 포함됩니다.

## 옵션

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `--games N` | 100 | 시뮬레이션할 판 수 (기본 모드와 `--skills`) |
| `--skills` | – | `--games N` 판을 돌려 스킬 피해 비중·주력기 표를 스킬별 전체 목록으로 뽑고, 직업별 기본 풀 광역 검사를 PASS/FAIL 로 판정 |
| `--seed S` | 1 | 루트 시드. 같은 시드 + 같은 옵션이면 결과가 완전히 같음 |
| `--map M` | random | `plains` / `dark` / `desert` / `glacier` / `random`. random 이면 판마다 시드에서 파생해 선택 (`--dodge` 에서는 random 이면 평원) |
| `--day D` | 5 | 양 팀을 `generateOpponentTeam` 으로 만들 때의 육성 일차 (1~10). 1 은 갓 뽑은 팀, 10 은 완성 팀 수준 |
| `--cycle D` | – | `--day` 의 옛 이름. v0.3 스크립트 호환용 별칭이며 동작은 완전히 같음 |
| `--runs N` | 60 | `--monster` / `--rarity` 에서 쓸 표본 육성 수. 시드 `S`, `S+1`, … `S+N-1` |
| `--policy P` | greedy | 육성 자동 정책. `greedy` / `first` / `random` |
| `--determinism` | – | 같은 입력으로 전투를 두 번 돌려 틱마다 프레임 해시(유닛·이벤트·영역·거점)를 비교 |
| `--growth` | – | 10일 × 5스텝 육성을 자동 정책으로 끝까지 진행하고 분화 보장을 검증 |
| `--monster` | – | 매 일차 하급·중급·고급을 모두 싸워 난이도별·인원 구간별 승률표를 뽑음 (난이도 보정 도구) |
| `--rarity` | – | 선택지 등급 분포·등급별 예상 전투력 상승치·보장 등급 동작 검증 |
| `--dodge` | – | 광역 예고 회피율 측정 (판단력 80·민첩 70 vs 판단력 30·민첩 30) |
| `--trials N` | 400 | `--dodge` 유닛당 판정 횟수 (실전 표본도 영역이 이 수에 닿을 때까지 모음) |
| `--skill ID` | mage_blast | `--dodge` 시험 광역 스킬 id. `enemy_area` 또는 `line` 대상이어야 함 |
| `--telegraph T` | 스킬 값 | `--dodge` 예고 시간(초) 덮어쓰기. 기본은 `SkillDef.telegraphSec`, 없으면 기본 규칙(0.8 / 소형 근접 0.3) |
| `--radius R` | 스킬 값 | `--dodge` 영역 반경 덮어쓰기 (공식+이동 판정에만 적용. 실전 표본은 스킬 정의대로 싸움) |
| `--move M` | 50 | `--dodge` 두 시험 유닛의 이동속도 스탯 |
| `--json` | – | 표 대신 요약 JSON 을 stdout 에 출력 (다른 도구에 넘기기 좋음) |
| `--help` | – | 도움말 |

`--games=200` 처럼 `=` 로 붙여 써도 됩니다.

### 자동 정책 (`--policy`)

| 정책 | 선택지 | 몬스터 난이도 | 보너스 상점 |
|---|---|---|---|
| `greedy` (기본) | `estimatePowerDelta` 가 가장 큰 카드 (동점이면 앞 카드) | 항상 **중급** | 싼 스킬부터 하루 최대 2개 구매 후, 남은 포인트를 전부 스탯 훈련에 사용 |
| `first` | 항상 0번 카드 | 항상 첫 카드(하급) | 구매 없음 |
| `random` | 시드에서 파생한 난수로 선택 | 난수로 선택 | 구매 없음 |

`greedy` 가 GDD 에서 말하는 "표준 성장 플레이어"에 해당합니다. 몬스터 난이도 보정(`--monster`)은 항상 `greedy` 로 돕니다.

`greedy` 의 상점 정책은 포인트를 남기지 않습니다(성장 곡선 실측용). 이 정책을 바꾸면 기준 플레이어의
전투력 곡선이 통째로 바뀌므로 `monsters.ts` 의 `EXPECTED_TEAM_POWER_BY_DAY` 와
`charGen.ts` 의 `OPPONENT_POWER_BY_DAY` 를 반드시 다시 측정해야 합니다.

기준 팀 구성(`pickDistinctJobs`)은 **탱커 또는 힐러 1명을 먼저 넣고** 나머지를 서로 다른 직업으로 채워 `TEAM_SIZE` 명을 만듭니다.
`generateOpponentTeam` 이 3일차부터 상대에게 같은 보장을 주기 때문에, 기준 플레이어만 보장이 없으면
표본의 상당 부분이 구조적으로 불리해져 모든 난이도 보정값이 그 편향 위에 맞춰집니다.
4인 팀에서는 한 명의 비중이 5인 때보다 커서 이 규칙이 더 중요합니다. 규칙을 바꿀 때는 위 두 표를 다시 측정하세요.
풀에서 `TEAM_SIZE` 명을 못 고르거나 `selectTeam` 뒤 팀 인원이 `TEAM_SIZE` 와 다르면 도구가 즉시 오류로 멈춥니다.

## 1. 대량 전투 (기본 모드)

```
npm run headless -- --games 200 --seed 1
npm run headless -- --games 500 --map desert --day 10
npm run headless -- --games 1000 --json > result.json
```

판마다 `hashSeed("시드:판번호:A")`, `...:B`, `...:battle`, `...:map` 으로 시드를 파생하므로
판 수를 늘려도 앞쪽 판의 입력은 바뀌지 않습니다 (`--games 100` 의 1~100판 = `--games 200` 의 1~100판).

전투는 `runToEnd()` 대신 `step()` 을 끝까지 불러 진행합니다 (결과는 완전히 같음). 틱마다 프레임의 `zones` 를 보고
광역 영역의 예고 시작과 impact 시점을 추적하기 위해서입니다.

출력 표:

- **전체 결과**: A 승 / B 승 / 무승부 비율, 평균 전투 시간(초)과 **목표 60~120초** 판정 (GDD §11 보정 목표. `--day 1` 은 `--day 10` 보다 짧아야 합니다).
  두 팀 모두 같은 방식으로 생성되므로 A 와 B 승률이 크게 다르면 스폰 대열이나 진영 처리에 편향이 있다는 뜻입니다.
- **맵별 A 승률**: 맵별 판수, A/B/무승부 비율, 평균 시간.
- **직업별**: 메인 직업마다 등장 횟수(캐릭터 단위), 승률, 무승부 비율, 평균 피해량, 평균 회복량, 생존율,
  평균 킬, 평균 스킬 사용 횟수. 승률 내림차순. 소환물의 피해·회복·킬은 `summon` 이벤트의 소환사에게 합산됩니다.
- **스킬 사용 상위 10**: `skill` 이벤트 기준 사용 횟수와 판당 횟수.
- **광역 영역(Zone)·회피 (판당 평균)**: 아래 설명.
- **스킬 피해 비중**: 전체 피해를 출처(스킬 즉시·광역 즉발 / 장판 / 지속 피해 / 기본 공격 / 소환물 …)로 나눈 표와
  **스킬 피해 비중·기본 공격 비중**, 10일차 목표(55~70% / 30~45%) 판정. 계산은 7절.
- **주력기 1회 피해 / 대상 최대 HP**: 사용 20회 이상인 피해 스킬마다 평균 1회 피해가 그 순간 대상 최대 HP 의 몇 % 인지와
  장판 초당 %. 단일 18~30% / 광역 즉발 12~20% (+장판) 목표 판정. 계산은 7절.
- **종료 사유**: `annihilation` / `timeout_hp` / `capture` / `timeout_draw` 등의 히스토그램.

### 광역 영역·회피 통계 (`--games`, `--growth` 공통)

| 항목 | 계산 |
|---|---|
| 광역 영역 생성 | `zone` 이벤트 수 (예고 시작. 아군 광역의 표시용 영역이 이벤트를 내면 그것도 포함) |
| 피해 광역 영역 | 프레임 `zones` 에 새로 나타난 영역 중 스킬이 `enemy_area` / `line` 이고 피해(또는 장판 `dpsCoef`)가 있는 것 |
| 회피 판정 | 피해 광역이 **예고 단계**로 나타난 틱에 영역 안에 있던, 살아 있고 기절·빙결·도발이 아닌 적 유닛 수 (= 회피 롤 횟수 추정) |
| 회피 성공 | `dodge` 이벤트 수 (인지 성공 = 영역 밖으로 달리기 시작) |
| 회피 성공률(인지) | 회피 성공 / 회피 판정 |
| 광역 피해 회피 비율 | 예고 시작 시 영역 안에 있었고 impact 때 살아 있던 유닛 중, impact 틱에 영역 **밖**에 있던 비율. 인지했지만 못 벗어난 유닛은 여기서 걸러집니다 |

impact 는 영역의 `phase` 가 `telegraph` 에서 다른 값(`flash` / `active`)으로 바뀐 첫 프레임, 또는 영역이 사라진 프레임으로 잡습니다.
`line` 영역의 포함 판정은 sim 과 같이 선분과의 수직 거리 ≤ 스킬 `radius`(= 폭) 를 씁니다. 예고 없는 스킬(`telegraphSec 0`)은 회피 판정을 세지 않습니다.
영역이 하나도 안 생기면 그 사실을 표 아래에 알려줍니다 (sim 미구현 또는 광역 스킬 미사용).

20판 이상이면 진행률을 stderr 에 표시합니다 (`--json` 일 때는 표시하지 않음).

## 2. 결정론 검증

```
npm run headless -- --determinism --seed 3 --map glacier --day 8
```

`--seed`/`--map`/`--day` 로 만든 0번 판의 입력을 JSON 으로 두 번 복사해 시뮬레이터 두 개를 만들고,
틱마다 `step()` 결과(유닛 스냅샷, 이벤트, **광역 영역 스냅샷**, 거점 상태, 종료 플래그)를 직렬화한 FNV-1a 해시를 비교합니다.

- **프레임 해시 비교**: 첫 불일치 틱과 어느 유닛/영역의 어느 필드가 달랐는지 출력. 관측된 광역 영역 수도 함께 표시.
- **최종 결과 비교**: `result()` 직렬화 비교.
- **입력 불변 검사**: 시뮬레이터가 `BattleInput` 객체를 수정했는지 검사 (경고만, PASS/FAIL 판정에는 포함하지 않음).

모두 통과하면 `결과: PASS`, 종료 코드 0. 실패 시 종료 코드 1 이므로 CI 에서 쓸 수 있습니다.

## 3. 육성 헤드리스 (`--growth`)

```
npm run headless -- --growth --seed 1
npm run headless -- --growth --policy random --seed 42
npm run headless -- --growth --seed 42 --json
```

`src/core/growth/run.ts` 상태 머신을 `--policy` 정책으로 10일 × 5스텝 끝까지 진행합니다.

1. 풀에서 앞에서부터 서로 다른 메인 직업 `TEAM_SIZE` 명을 고른다 (탱커/힐러 1명 우선, 팀 이름 "헤드리스 검증팀").
2. 선택 스텝(1·2·4)은 정책대로 카드 한 장을 고른다.
3. 몬스터 스텝(3)은 정책대로 난이도를 고르고 전투는 `runToEnd()` 로 즉시 끝낸다.
4. 전투 스텝(5)은 틱 추적으로 끝까지 진행해 광역·회피 통계를 모은다 (결과는 `runToEnd()` 와 같음).
5. 하루 마무리에서 (greedy 라면) 싼 스킬부터 최대 2개를 사고, 남은 포인트를 스탯 훈련에 전부 쓴 뒤 다음 날로 넘어간다.

출력:

- **일차별 진행**: 일차, 4:4 맵, 그날 고른 카드 3장의 등급, 몬스터 난이도와 승패, **몬스터 편성 인원**, 4:4 승패, **4:4 전투 시간**,
  그날 획득한 포인트, 팀 평균 스탯합, 팀 전투력(팀원 `powerRating` 합).
- **일차별 고른 선택지**: 몬스터 종류 이름과 고른 카드 제목 (도박형은 성공/실패 표시).
- **요약 줄**: 4:4 전적, 몬스터 전적, 총 획득 포인트, 상점에서 산 스킬 수, 남은 포인트,
  4:4 평균 전투 시간과 1일차 → 10일차 전투 시간(1일차가 더 짧아야 함. 표본 하나라 참고용),
  최종 평균 스탯합/전투력, 보장 등급(`rarityFloor`) 충족 횟수(PASS/FAIL).
- **광역 영역·회피**: 10판의 4:4 전투에서 모은 판당 평균 (계산은 1절과 같음).
- **직업 분화 보장 검증**: 캐릭터마다 예정 일차(`RunState.subJobChoiceDay`), 분화 선택지가 실제로 등장한
  `(일차:스텝)`, 직업 변경 이력, 최종 세부 직업, PASS/FAIL 과 실패 사유.
  판정 기준은 **첫 등장이 4~6일차 안**이고, 다른 날 다시 등장한 경우는
  (a) 그때까지 아직 분화하지 않았다면(정책이 다른 카드를 골라 보장이 이어진 경우) 정상,
  (b) 이미 분화한 상태였다면 **그 사이에 직업 변경이 있었을 때만**(재분화) 인정합니다.
  등장 표기는 `일차:스텝` 이고 뒤의 `*` 는 이미 분화된 상태에서 다시 제시되었다는 뜻입니다.

모든 캐릭터가 PASS 이고 10일차가 `done` 까지 도달하면 종료 코드 0, 아니면 1.

### 4:4 상대 강도 보정

`--growth` 를 시드를 바꿔가며 여러 번 돌려 일차별 4:4 승률을 보고 `charGen.ts` 의
`OPPONENT_POWER_BY_DAY` (일차별 상대팀 목표 전투력)를 조정합니다. `generateOpponentTeam` 은 팀을 만든 뒤
`fitTeamPower` 로 이 목표치에 스탯을 맞추므로, 상대 강도 곡선은 그 표 하나로 결정됩니다.
목표는 표준 성장 플레이어 기준 10일차 상대 대비 45~55% 입니다. 대량 확인은 `--games N --day 10` 이 빠릅니다
(양 팀이 모두 생성 팀이므로 A/B 승률이 50% 근처여야 하고, 평균 시간이 60~120초 안이어야 합니다).

## 4. 몬스터 난이도 보정 (`--monster`)

```
npm run headless -- --monster --runs 60
npm run headless -- --monster --runs 200 --seed 100 --json > monster.json
```

`greedy` 정책으로 `--runs` 회의 표준 육성을 돌리면서, **매 일차 3스텝마다 하급·중급·고급 세 장을 전부 싸워 봅니다.**
싸움에는 팀과 몬스터 편성의 깊은 복사본만 쓰고 전투 시드도 따로 파생하므로(`hashSeed("시드:일차:probe:난이도:몬스터id")`)
진행 중인 육성 결과는 전혀 바뀌지 않습니다. 실제 진행은 그대로 중급을 골라 이어집니다.

출력:

- **일차 × 난이도 승률**: 각 칸은 `승률 (평균 전투 시간)`. 일차별 곡선이 평평한지 여기서 봅니다.
- **난이도별 전체 승률과 목표**: 목표(하급 95~100% / 중급 80% / 고급 50%)와의 차이를 `+xx.xp` 로 표시하고,
  하급은 95% 이상, 중급·고급은 오차 ±5%p 안이면 `OK`, 아니면 `조정 필요`.
- **난이도 × 인원 구간 승률**: 편성 인원을 **1~2명 / 3~4명 / 5~8명** 으로 묶어 난이도마다 승률·판수·평균 시간을 보이고,
  표본이 있는 구간들의 승률 최대−최소를 `편차` 로 표시합니다. **±8%p 이내**면 `OK` (GDD §7.3.1: 1기 보스와 8기 떼의 편차 목표).
  편차가 크면 `TIER_POWER_RATIO` 가 아니라 해당 인원 편성의 `MonsterDef.powerScale` 을 움직입니다.
- **난이도별 전투 시간 분포**: 평균·중앙값·40초 미만 비율·120초 초과 비율. 평균만 보면 긴 꼬리에 가려
  중앙값이 목표 하한 아래로 내려간 것을 놓치므로, 판정은 중앙값과 두 비율로 합니다.
  (몬스터 전투는 초반 일차에 4:4 보다 짧게 끝나도 되므로 하한을 40초로 둡니다.)
- **몬스터 종별 승률과 전투 시간**: 종마다 **인원**, 승률, 평균, 중앙값, 120초 초과 비율. 인원 오름차순.
  난이도 평균은 맞는데 특정 종만 크게 벗어나는 경우를 여기서 잡고, 그 종의 `MonsterDef.powerScale` 만 움직입니다.
- **팀 전투력** 열: 그 일차 3스텝(몬스터 전투 직전)의 실측 평균 팀 전투력.
  `monsters.ts` 의 `EXPECTED_TEAM_POWER_BY_DAY` 는 이 열을 그대로 옮겨 적은 값입니다.
- 인원이 `MONSTER_TEAM_MIN`~`MONSTER_TEAM_MAX` 밖인 편성이 관측되면 상단에 경고를 냅니다.

보정 순서는 이렇습니다.

1. **일차별 기울기**를 먼저 잡는다 — `EXPECTED_TEAM_POWER_BY_DAY` 를 위 '팀 전투력' 열로 갱신하고,
   그래도 남는 기울기는 `DAY_DIFFICULTY_EXPONENT` 로 다듬는다.
2. **전체 수준**을 맞춘다 — `TIER_POWER_RATIO`.
3. **인원 구간·종별 편차**를 맞춘다 — `MonsterDef.powerScale`, `MonsterUnitTemplate.derivedMult`.
   1기 보스는 집중 사격에 빨리 무너지는 대신 한 기가 강하고, 8기 떼는 광역에 약합니다. 인원 구간표의 편차가 ±8%p 안에 들어올 때까지
   1~2명 편성과 5~8명 편성의 `powerScale` 을 반대 방향으로 움직입니다.

승률은 전투력에 매우 민감합니다(1% → 4~6%p). 한 번에 0.01~0.02 씩만 움직이고 매번 다시 측정하세요.
시드군만 바꿔도 ±5%p 는 움직이므로 최소 두 시드군에서 확인해야 합니다
(예: `--runs 40 --seed 1` 과 `--runs 40 --seed 201`).

전투 수가 많습니다. `--runs 60` 이면 난이도 시험 1,800판 + 실제 육성 전투 1,200판입니다. 진행률은 stderr 에 표시됩니다.
표본 60회면 난이도당 600판이라 승률 오차가 ±2%p 수준이지만, 인원 구간표는 한 구간에 종이 1~2개만 들어가므로 구간당 표본이 그 1/3 이하입니다.
인원 구간 편차를 볼 때는 `--runs 120` 이상을 권합니다.

## 5. 선택지 등급 모델 검증 (`--rarity`)

```
npm run headless -- --rarity --runs 60
npm run headless -- --rarity --runs 200 --json > rarity.json
```

전투 없이 `generateChoices` 를 일차 1~10 × 선택 스텝 1·2·4 로 반복 호출해 대량의 카드 표본을 만듭니다
(`--runs 60` 이면 60팀 × 30세트 = 분포용 1,800세트 / 5,400장). 세트마다 보장 등급을 건 세트를 한 번 더
생성해 `rarityFloor` 동작을 따로 검증합니다 — 보장을 건 세트는 상위 등급이 섞이므로 분포 표본에는 넣지 않습니다.
분화 보장이 분포를 가리지 않도록 표본 생성 시 `subJobChoiceDay` 는 비웁니다(분화 보장 자체는 `--growth` 가 검증).
`generateChoices` 를 부를 수 없으면 실제 육성을 돌려 제시된 세트를 모으는 방식으로 자동 전환합니다(느림, stderr 에 안내).

출력:

- **일차 구간별 등급 분포**: `관측 % / 기대 %`. 기대값은 GDD §7.4.1 의 가중치
  (1~3일 52/32/13/3, 4~7일 44/34/17/5, 8~10일 34/35/22/9).
- **등급별 powerDelta 와 스탯 상승량**: 카드 수, 비율, 평균/최소/최대 `powerDelta`,
  평균 순 스탯 상승량과 GDD §7.4.2 기준값(일반 10~16 / 레어 20~30 / 에픽 36~50 / 전설 60~85), 기준 구간 안이면 `OK`.
  이 기준은 4인 팀에서도 그대로입니다 (한 명당 배분은 늘지만 총량 기준은 바뀌지 않음).
  스탯 상승량은 순수 스탯 카드(집중·합동·편중·도박)의 **순 변화량(상승 − 하락)** 입니다. 하락을 빼지 않으면
  편중 훈련처럼 위험을 지고 상승을 부풀린 카드가 기준을 넘은 것처럼 보입니다. 스킬·시너지·분화·맵 적응·희생은
  보상이 스탯만이 아니라 제외합니다.
  `powerDelta` 는 `estimatePowerDelta(team, choice)` 로 계산합니다 (스탯 1 = 1, 스킬 = 25, 시너지 = 20, 분화 = 35, 맵 적응 1 = 0.4).
  등급이 올라갈수록 평균 `powerDelta` 가 커지고 레어 이상의 **최소값이 음수가 아니어야** 합니다
  (카드 색이 값을 과장하면 안 됩니다). 등급 예산 밖의 '직업 변경' 카드만 예외로 항상 일반이며 음수일 수 있습니다.
- **선택지 종류별**: 종류마다 등장 비율, 평균 `powerDelta`, 최빈 등급.
- **보장 등급(`rarityFloor`) 검증**: 레어/에픽/전설 보장을 걸었을 때 세트 3장 중 최소 1장이
  그 등급 이상이었는지. 하나라도 어기면 FAIL 이고 종료 코드 1 입니다.

분화 보장 세트(한 캐릭터의 세부 직업 3장)는 분포를 왜곡하므로 표본에서 빼고 개수만 따로 셉니다.
'직업 변경' 카드는 희귀도 롤을 거치지 않는 특수 카드(세트당 최대 1장, 낮은 확률)라 일반 등급 비율을 1%p 정도 밀어 올립니다.

## 6. 광역 예고 회피율 (`--dodge`)

```
npm run headless -- --dodge
npm run headless -- --dodge --trials 1000 --seed 7
npm run headless -- --dodge --skill mage_fire_storm --move 40
npm run headless -- --dodge --telegraph 0.3 --radius 2.0 --json
```

GDD §4.4 의 회피 공식과 §11 의 보정 목표
(**판단력 80 · 민첩 70 유닛은 예고 0.8초 광역을 절반 이상 회피, 판단력 30 · 민첩 30 유닛은 30% 미만**)를 두 방법으로 측정합니다.

시험 유닛은 검사(`swordsman`) 직업의 합성 캐릭터 3기입니다. 모든 스탯 40, 맵 적응도 50, 스킬 없음, 판단력·민첩·이동속도만 다릅니다.

| 유닛 | 판단력 | 민첩 | 이동속도 | 목표 |
|---|---|---|---|---|
| 판단력 80·민첩 70 | 80 | 70 | `--move` (기본 50) | 실제 회피율 ≥ 50% |
| 판단력 30·민첩 30 | 30 | 30 | `--move` (기본 50) | 실제 회피율 < 30% |
| 참고: 판단력 30·민첩 30·이동속도 20 | 30 | 30 | 20 | 판정 없음 (이동속도 효과 비교용) |

### 6.1 공식 + 이동 판정

유닛당 `--trials` 회(기본 400) 다음을 반복합니다.

1. 인지 롤: `p = clamp(0.10 + 판단력 × 0.006 + 민첩 × 0.003, 0.05, 0.85)`, 예고 시간이 0.5초 미만이면 절반. `Rng(hashSeed("시드:dodge:formula:유닛번호"))` 로 롤.
2. 이동 판정: `computeDerived` 의 이동 속도 × 1.15 로 예고 시간(틱 단위로 반올림) 동안 갈 수 있는 거리와,
   영역 경계 밖 +0.6 까지 필요한 거리를 비교합니다.
   - **중심 기준**: 유닛이 영역 중심에 있다고 가정 (`enemy_area` 는 대상 중심에 떨어지므로 주 대상의 경우). 필요 거리 = 반경 + 0.6.
   - **임의 위치 기준**: 영역 안 면적 균등 위치(`r = R·√u`). 필요 거리 = (반경 − r) + 0.6.
3. 실제 회피 = 인지 성공 ∧ 이동 성공.

표에는 인지 확률(공식값), 관측 인지율, 이동 가능 거리(초), 중심 기준 필요 거리, 두 가지 실제 회피율, 목표, 판정이 나옵니다.
목표 판정은 **중심 기준**(더 엄격한 쪽) 으로 합니다.
`--radius` / `--telegraph` / `--move` 로 조합을 바꿔 보며 "어느 이동속도부터 벗어나는가"를 확인할 수 있습니다.

sim 이 `dodgeChance`(또는 `dodgeChanceOf` / `computeDodgeChance`) 를 내보내면 `(판단력, 민첩, 예고시간)` 으로 불러
공식과 1e-6 안에서 일치하는지 대조하고 결과를 첫 줄에 적습니다. 인자 형태가 달라 호출이 실패하면 그 사실만 알리고 공식은 도구 구현으로 계산합니다.

### 6.2 실전 표본

시험 스킬(기본 `mage_blast`, 반경 2.5 · 사거리 7 · 예고 0.8초) 하나만 가진 합성 시전자 1기(A 팀)와
**같은 시험 유닛 2기**(B 팀)를 실제 전투에 붙입니다. 2기를 넣는 이유는 광역 스킬의 AI 조건이 '적 2명 이상 모임'이기 때문이고,
덕분에 영역 하나에 판정 표본이 둘씩 잡힙니다. 시전자는 `derivedMult` 로 HP 를 크게, 공격력을 낮게 잡아 전투가 제한시간까지 이어지며
영역이 계속 생성되고, 시험 유닛은 공격력을 거의 0 으로 만들어 시전자를 죽이지 못합니다.
판마다 `hashSeed("시드:dodge:battle:유닛번호:판번호")` 로 전투 시드를 파생하고, 영역 수가 `--trials` 에 닿거나 200판이 될 때까지 돕니다.
첫 판에서 영역이 하나도 안 생기면 sim 이 Zone 을 만들지 않는 것이므로 바로 멈추고 `측정 불가` 로 표시합니다.

각 판은 1절의 프레임 추적으로 시전자 영역만 골라 다음을 셉니다.

| 열 | 뜻 |
|---|---|
| 영역 | 시험 스킬로 생성된 피해 광역 영역 수 |
| 회피 판정 | 예고 시작 시 영역 안에 있던 시험 유닛 수 |
| dodge 이벤트 | 시험 유닛의 `dodge` 이벤트 수 → **인지율** = dodge / 회피 판정 |
| 노출 / 벗어남 | impact 때 살아 있던 유닛 수 / 그중 영역 밖에 있던 수 → **실제 회피율** = 벗어남 / 노출 |

실전 표본의 목표 판정은 실제 회피율로 합니다. 인지율은 공식이 sim 안에서 그대로 쓰이는지, 실제 회피율은 이동·탈출 로직이 예고 시간 안에
실제로 벗어나게 하는지를 각각 봅니다. 두 값이 크게 다르면(예: 인지 80%, 실제 40%) 회피 이동 쪽(속도·탈출점·충돌·이동 시작 틱)을 봐야 합니다.
`--radius` / `--telegraph` 덮어쓰기는 실전 표본에는 적용되지 않습니다 (스킬 정의대로 싸움). 다른 반경을 실전으로 보려면 `--skill` 을 바꾸세요.

### 6.3 판정과 종료 코드

- `보정 목표 [4] 회피 — 공식+이동 판정: PASS/FAIL, 실전 표본: PASS/FAIL/측정 불가`
- 두 목표 유닛이 공식+이동 판정을 모두 통과하고 실전 표본이 FAIL 이 아니면(측정 불가는 허용) `결과: PASS`, 종료 코드 0. 아니면 1.
- 판단력 30·민첩 30 의 공식 인지 확률은 37% 입니다. 이동속도가 충분해 인지한 만큼 전부 벗어나면 30% 목표를 넘기므로,
  그 경우 도구가 참고 문구를 덧붙입니다. 이 목표는 "느린 유닛은 인지해도 못 벗어난다"를 전제로 하므로 반경·예고 시간·이동속도의 조합이나
  공식 계수가 그 전제를 실제로 만족하는지 여기서 확인합니다.

## 7. 스킬 피해 비중 · 주력기 1회 피해 (`--games` 공통, `--skills`)

```
npm run headless -- --games 200 --day 10                 # 표 두 개가 --games 출력 끝에 붙는다
npm run headless -- --skills --games 200 --day 10        # 스킬별 전체 목록 + 광역 없는 직업 검사
npm run headless -- --skills --games 300 --seed 4242 --day 10 --json > skills.json
```

설계 사양 [3] "스킬 맞는 체감이 나야 한다" 의 목표 지표를 헤드리스로 잽니다. 판마다의 입력은 `--games` 와 같은 시드 규칙이라
`--games 200` 과 `--skills --games 200` 은 같은 200판을 봅니다. 두 팀 모두 `generateOpponentTeam` 으로 만든 팀이므로
**목표는 `--day 10` 에서 판정**하고, 다른 일차는 참고값으로 표시합니다.

| 지표 | 목표 (10일차) | 어디서 |
|---|---|---|
| 스킬 피해 비중 = 스킬(광역·장판·지속 피해 포함) 피해 / 전체 피해 | 55~70% | 스킬 피해 비중 표 |
| 기본 공격 비중 | 30~45% | 같은 표 |
| 단일 대상 주력기 1회 피해 / 대상 최대 HP | 18~30% | 주력기 표 |
| 광역 즉발 대상당 1회 피해 / 대상 최대 HP | 12~20% + 장판 | 주력기 표 |
| 장판 초당 피해 / 대상 최대 HP | 목표 없음 (참고). '장판 총량(풀히트)' = 초당 % × 지속 초 | 주력기 표 |

### 7.1 출처 분류 방법 (sim 이벤트 기반)

sim 이 프레임 이벤트(`BattleFrame.events`)에 피해 출처를 실어 줍니다 (`types.ts` `BattleEvent`). 도구는 전투를 `step()` 으로 진행하며 틱마다 그것을 더합니다.

| 이벤트 | 분류 |
|---|---|
| `attack` 에 `skillId` 가 있음 | 그 스킬의 즉시 피해 또는 광역 impact 피해 (**스킬 즉시·광역 즉발**). 비-miss 는 스킬별 피격·1회 피해·`damage / 대상 maxHp` 표본 |
| `attack` 에 `skillId` 가 없음 | **캐릭터 기본 공격**. 시전자 스냅샷의 `job` 이 `summon` 이면 **소환물 기본 공격** |
| `zone_damage` | **장판** 한 틱의 피해 (`skillId` 로 스킬별 합산). 한 틱에 장판 하나만 맞은 유닛의 값은 '장판 초당 %' 표본 |
| `dot` | **지속 피해**(화상·중독) 한 틱. 상태에 스킬 id 가 없어 어느 스킬이 걸었는지는 모릅니다 → 전체 비중에는 들어가고 스킬별 합에는 안 들어감 |
| `reflect` | **반사** |

- **전체 피해 = Σ `unitStats.damageTaken`** (양 팀). **스킬 피해 비중 = (전체 − 캐릭터 기본 공격 − 소환물 기본 공격) / 전체**.
- **미분류** = 전체 − 분류 합. `attack` / `reflect` 이벤트의 `damage` 가 반올림이라 이벤트당 ±0.5 만큼만 생깁니다 (측정에서 0.0%). 10% 를 넘으면
  sim 에 이벤트를 내지 않는 피해 경로가 생긴 것이므로 경고를 냅니다.
- `zone_damage` 와 `dot` 는 틱 단위라 `BattleResult.events` 에는 들어가지 않고 프레임 이벤트에만 실립니다. 그래서 이 도구는 `runToEnd()` 가 아니라
  `step()` 으로 진행합니다 (결과는 같습니다).

### 7.2 주력기 표의 열

| 열 | 뜻 |
|---|---|
| 분류 | `단일`(광역이 아닌 대상) / `광역`(`enemy_area` · `line`). 장판이 있으면 `+장판`. 피해 효과 없는 스킬은 `피해 없음` |
| 사용 / 판당 | `skill` 이벤트 수 / 판당 |
| 피격 | 스킬로 분류된 비-miss `attack` 이벤트 수 (광역은 대상당 1) |
| 평균 1회 피해 | 피격당 평균 피해 |
| 대상 HP 대비 | 피격마다 `damage / 그 순간 대상 스냅샷의 maxHp` 의 평균 |
| 장판 초당 | 한 틱에 장판 **하나만** 맞은 유닛의 `zone_damage.damage / maxHp` 를 초당으로 환산 (여러 장판이 겹친 틱은 제외) |
| 장판 총량(풀히트) | 장판 초당 % × `linger.durationSec` — 끝까지 서 있었을 때의 총량 |
| 목표 / 판정 | 단일 18~30%, 광역 12~20%. 피격 20회 미만이면 `표본 부족`. 하한 미만 `약함`, 상한 초과 `강함` |

`--games` 는 사용 20회 이상인 피해 스킬만, `--skills` 는 그 표에 더해 **사용된 액티브 스킬 전부**를 총 피해·비중(전체 대비)과 함께 비중 내림차순으로 보여줍니다.
몬스터 전용(`mon_`) 스킬도 등장하면 같은 기준으로 표시됩니다 (4:4 생성 팀에는 나오지 않음. 설계 [3]: 몬스터 스킬도 같은 배율로 올려 관계를 유지).

### 7.3 광역 없는 직업 검사 (`--skills`)

직업마다 **기본 풀 = `starterSkills` ∪ `skillPool`** (분화 전, `JobDef` 기준) 에서 적 광역 피해 스킬
(`enemy_area` / `line` 이고 피해 효과가 있거나 장판 `dpsCoef > 0`) 을 찾습니다. 한 개 이상이면 PASS.
마법사는 설계 [1] 대로 **시작 스킬 후보가 전부 광역 피해 스킬**인지도 봅니다. 둘 다 통과해야 `결과: PASS`, 종료 코드 0.

### 7.4 보정 순서 (설계 [3])

1. 스킬 계수 출발점(단일 ×1.6, 광역 즉발 ×1.5, 장판 dps ×1.4, 회복 ×1.4)을 넣고 `--skills --games 300 --day 10` 으로 비중과 주력기 표를 봅니다.
2. 비중이 55% 에 못 미치면 계수가 아니라 **사용 빈도**(쿨타임·MP·AI 조건)도 같이 봅니다 — 판당 사용이 1 미만인 주력기는 계수를 올려도 비중이 안 오릅니다.
3. 전투 시간이 60초 아래로 내려가면 **HP 상수(`stats.ts` 최대 HP)나 방어를 올려** 맞춥니다. 스킬 계수를 다시 깎지 않습니다 (설계 [3]).
   HP 를 올리면 '대상 HP 대비' 가 같이 내려가므로 두 표를 번갈아 봅니다.
4. 시드 3그룹(1, 4242, 9001)으로 확인합니다. 비중은 시드에 덜 민감하지만 개별 스킬의 % 는 표본 20~40회에서 ±2%p 흔들립니다.

## 종료 코드

| 코드 | 의미 |
|---|---|
| 0 | 정상 (검증 모드는 PASS) |
| 1 | `--determinism` / `--growth` / `--rarity` / `--dodge` / `--skills` 검증 실패, 또는 실행 중 오류 |
| 2 | 잘못된 옵션 |

`--monster` 는 측정 도구이므로 목표 승률을 벗어나도 0 을 돌려줍니다. `--games` 도 평균 시간·스킬 비중 목표를 벗어나도 0 입니다.
`--skills` 는 광역 없는 직업 검사(7.3)만 종료 코드에 반영하고, 스킬 비중·주력기 목표는 표시만 합니다.

## 시드 파생 규칙

전부 `src/core/rng.ts` 의 `Rng` 와 `hashSeed` 만 사용합니다. `Math.random`, `Date` 는 쓰지 않습니다.

| 용도 | 시드 |
|---|---|
| 판 g 의 맵 (`--map random`) | `hashSeed("S:g:map")` |
| 판 g 의 팀 A / B | `hashSeed("S:g:A")` / `hashSeed("S:g:B")` |
| 판 g 의 전투 | `hashSeed("S:g:battle")` |
| `--skills` 의 판 g | `--games` 와 완전히 같음 (위 세 줄) |
| 육성 모드 | `newRun(S)` 이후는 run.ts 가 `hashSeed("S:일차:스텝:용도:…")` 로 파생 |
| `random` 정책의 카드/난이도 선택 | `hashSeed("S:일차:스텝:choice")` / `...:monster` |
| `--monster` 의 난이도 시험 전투 | `hashSeed("S:일차:probe:난이도:몬스터id")` |
| `--rarity` 의 선택지 생성 | `hashSeed("S:일차:스텝:rarity")` |
| `--rarity` 의 보장 등급 검증 세트 | `hashSeed("S:일차:스텝:floor:등급")` |
| `--dodge` 의 공식 롤 | `hashSeed("S:dodge:formula:유닛번호")` |
| `--dodge` 의 실전 전투 | `hashSeed("S:dodge:battle:유닛번호:판번호")` |

같은 옵션이면 몇 번을 돌려도 출력이 완전히 같습니다.

## 구현 메모

- 육성 모듈(`run.ts`, `choices.ts`)은 육성 모드에서만 **동적 import** 합니다. 육성 쪽이 수정 중이어도
  `--games` / `--determinism` / `--dodge` 는 그대로 동작합니다.
- 상태 머신 함수는 이름 후보 목록으로 찾습니다(`pickChoice` / `pickMonster` / `finishMonsterBattle` /
  `finishDay` 등). 이름이 달라 못 찾으면 "시도한 이름" 을 한국어로 알려줍니다.
  `estimatePowerDelta` 가 없으면 카드의 `Choice.powerDelta` 값을 대신 씁니다.
- `BattleFrame.zones` 가 비어 있거나 없는(구버전 sim) 프레임도 안전하게 처리합니다. 그 경우 광역·회피 통계는 전부 0 이고 안내 문구가 붙습니다.
- 회피 판정 수는 프레임 기하로 추정한 값입니다. sim 이 이동속도 0 인 소환물(포탑)을 제외하는 것까지는 스냅샷에서 알 수 없어 그 수만큼 약간 많게 셀 수 있습니다.
- 피해 출처(스킬/기본 공격/장판/지속 피해/반사)는 7.1절대로 sim 이벤트에서 읽습니다. `runBattleTracked` 가 회피 추적과 같은 프레임 순회 안에서 `attributeFrameDamage` 를 불러
  판당 `DamageStats` 를 만들고, `--games` / `--skills` 가 `addDamageStats` 로 합쳐 `damageSummaryOf` 로 표를 만듭니다.
  `--growth` / `--monster` / `--dodge` 는 같은 함수를 지나가지만 그 결과를 쓰지 않습니다.

## 활용 팁

- 직업 밸런스: `--games 1000 --day 10` 으로 완성 팀 기준 승률 표를 보고, 50% 에서 크게 벗어나는 직업의
  `statProfile`/스킬 계수를 조정합니다. 광역 예고 도입 뒤에는 마법사·대검사의 승률과 '광역 피해 회피 비율'을 함께 봅니다.
  회피 비율이 높으면 광역 피해 계수를 1.15~1.3배 안에서 올리는 것이 허용됩니다 (GDD §6.5.6).
- 전투 시간: `--games 300 --day 1` 과 `--games 300 --day 10` 의 평균 시간을 비교합니다. 1일차가 더 짧아야 하고 둘 다 60~120초 안이어야 합니다.
- 스킬 위력: `--skills --games 300 --day 10` 으로 스킬 피해 비중(55~70%)과 주력기 '대상 HP 대비'(단일 18~30% / 광역 12~20%)를 봅니다.
  판정이 `약함` 인 스킬은 계수를, 판당 사용이 낮은 스킬은 쿨타임·AI 조건을 손봅니다. 전투 시간이 짧아지면 HP 상수로 맞춥니다 (7.4절).
- 맵 밸런스: `--map` 을 바꿔가며 종료 사유 분포를 봅니다. 사막에서 `timeout_hp` 가 대부분이면 제한시간이 짧거나 피해량이 낮은 것입니다.
- 몬스터 밸런스: `--monster` → `powerScale`/`derivedMult` 수정 → 다시 `--monster`. 일차별 표에서 특정 구간만
  꺼진다면 일차 스케일링 곡선을, 전 구간이 고르게 낮다면 `TIER_POWER_RATIO` 를, 인원 구간표가 벌어지면 해당 인원 편성의 `powerScale` 을 손봅니다.
- 회피: sim 의 회피 이동 로직을 고친 뒤에는 `--dodge` 로 인지율과 실제 회피율이 같은 방향으로 움직이는지 확인합니다.
- 보상 균형: `--growth --json` 의 `days[].pointsEarned` 합과 `finalTeamPower` 로 몬스터 보상이 4:4 보상을 압도하지 않는지 봅니다.
- 시뮬레이터를 고친 뒤에는 항상 `--determinism` 을 한 번 돌려 순회 순서나 부동소수점 문제로 결정론이 깨지지 않았는지 확인합니다. 영역 스냅샷도 해시에 들어갑니다.
- 결과를 비교할 때는 `--json` 출력을 파일로 저장해 두고 diff 하는 것이 편합니다.
