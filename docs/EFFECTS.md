# 스킬 이펙트 에셋 규격 (v0.9)

전투 관전 화면의 **도트 모드**(기본)가 쓰는 스킬 이펙트 규격. 작가는 이 문서만 보고 그대로 그릴 수 있어야 한다.
코드 계약은 `src/ui/pixel/fx/fxTypes.ts` (`FxMeta`, `FX_KEYS`, `FX_DEFAULT_META`, `parseFxMeta`) 에 있고, 이 문서와 항상 일치해야 한다.

캐릭터 스프라이트 규격은 [SPRITES.md](SPRITES.md) 에 따로 있다. 두 규격은 **배율이 같다** (1 맵 유닛 = 32 px).
이펙트 에셋을 `public/effects/` 에 넣으면 코드 수정 없이 코드 생성 임시 이펙트를 대체한다. 넣지 않으면 임시 이펙트가 계속 나온다.

## 1. 프레임과 시트

| 항목 | 값 |
|---|---|
| 시트 구성 | **한 줄(1행)**. 프레임을 왼쪽 → 오른쪽으로 나열한다. 스프라이트와 달리 행이 여러 개가 아니다 |
| 프레임 크기 | **키마다 다르다** (32×32 / 48×48 / 64×64, 장판 테두리는 반경마다 160×160 ~ 384×384). §4 의 표를 따른다 |
| 시트 크기 | 폭 = `frameW × frames`, 높이 = `frameH`. 남는 칸을 두지 않는다 (검사기가 정확히 이 크기를 요구한다) |
| 파일 | 투명 PNG. 알파는 **0 또는 255 만** (반투명 픽셀 금지) |
| 앵커 | 대개 프레임 **중심** (32×32 → (16,16), 48×48 → (24,24), 64×64 → (32,32), 장판 테두리 224×224 → (112,112)). 예외 두 가지: `slash_*` 는 **(16,32)** = 왼쪽 가운데(손 위치), `zone_fill_*` 는 **(0,0)** = 타일 원점(좌상단) |
| 화면 크기 | 32 px = 맵 **1 유닛**. 즉 64×64 이펙트는 맵 2 유닛, 48×48 은 1.5 유닛, 32×32 는 1 유닛. 장판 테두리 224×224 는 맵 7 유닛 = 지름(반경 3.5 × 2) |
| 합성 | `blend`: `add` = 가산 합성(빛나는 것), `normal` = 일반. §3 참고 |
| 방향 | 투사체(`proj_*`)와 베기(`slash_*`) 는 **오른쪽(진행·공격 방향) 기준**으로 그린다. 코드가 앵커를 축으로 회전시킨다 (좌우 미러는 하지 않는다). 나머지는 회전하지 않는다 — 장판 테두리(`zone_ring_*`)도 **회전하지 않는다**. 원 한 장을 그대로 얹는다 |
| 팔레트 | 제한 없음. 단 계열 키는 §5 의 계열 색을 기준으로 잡아 계열이 한눈에 구분되게 한다 |

### 시트 배치 그림

```
  64×64 · 6프레임 (impact_fire) → 시트 384 × 64
        열 0     열 1     열 2     열 3     열 4     열 5
      ┌────────┬────────┬────────┬────────┬────────┬────────┐
행 0  │ 프레임0│ 프레임1│ 프레임2│ 프레임3│ 프레임4│ 프레임5│  20fps 1회 (0.30초)
      └────────┴────────┴────────┴────────┴────────┴────────┘
       프레임 n 의 픽셀 원점 = (n × frameW, 0).  행은 언제나 하나뿐이다.

  32×32 · 4프레임 (proj_arrow) → 시트 128 × 32
      ┌──────┬──────┬──────┬──────┐
      │  0   │  1   │  2   │  3   │   12fps 반복
      └──────┴──────┴──────┴──────┘

       한 프레임 안 (64×64 기준):
       (0,0) ┌────────────────┐
             │                │
             │       ✦        │
             │   ← ●  ▶ →     │  ← 중심 (32,32) = 앵커.
             │       ✦        │     이 점이 이펙트가 터지는 맵 좌표에 놓인다
             │                │
             └────────────────┘ (63,63)
```

앵커가 뜻하는 것은 계열마다 다르다.

| 계열 | 앵커 | 앵커가 놓이는 곳 |
|---|---|---|
| `impact_*`, `death_poof`, `summon_circle` | 프레임 중심 (32,32) | 이펙트의 **중심** — 폭발 지점 / 사망·소환 유닛의 **발 위치** |
| `zone_ring_<계열>_r<반경×10>` | 프레임 **중앙** (크기의 절반. 224×224 → (112,112)) | **원 전체의 중심** = 장판의 중심 좌표. 테두리는 프레임 가장자리에 닿는다 |
| `proj_*` | 프레임 중심 (16,16) | 투사체의 **진행 방향 기준 중심**. 앵커를 축으로 회전한다. 머리는 오른쪽, 꼬리는 왼쪽 |
| `slash_*` | **(16,32)** 왼쪽 가운데 | 시전자의 **손 위치**. 칼자국의 호가 이 점을 중심으로 돌고, 칼날은 앵커의 **오른쪽(공격 방향)** 으로 뻗는다 |
| `zone_fill_*` | **(0,0)** 좌상단 | 타일의 **원점**. 중심이 아니다. 코드가 이 점을 기준으로 타일을 격자에 맞춰 이어 붙인다 |
| `cast_*` | 프레임 중심 (24,24) | 시전자의 **발 위치** (스프라이트 앵커와 같은 점). 유닛보다 아래에 깔린다 |
| `status_freeze`, `status_shield`, `buff_ring` | 프레임 중심 (32×32 는 (16,16), `buff_ring` 은 (24,24)) | 유닛의 **발 위치**. 유닛보다 아래에 깔린다 |
| `status_stun`, `status_burn` | 프레임 중심 (16,16) | 유닛의 **머리 위** (발에서 머리 높이 + 0.35 유닛). 유닛 위에 얹힌다 |
| `heal_burst` | 프레임 중심 (24,24) | 대상의 발에서 **0.8 유닛 위** (몸통 한가운데) |
| `crit_star` | 프레임 중심 (16,16) | 대상 유닛의 **몸통 위쪽** (발에서 1.1 유닛 위) |
| `dodge_puff` | 프레임 중심 (16,16) | 대상 유닛의 **발 위치**. 프레임 중심이 발에 오므로 먼지는 아래 절반이 아니라 **중심 둘레로** 퍼져야 한다 |

## 2. 파일과 메타데이터

```
public/effects/<key>.png     시트 이미지 (1행)
public/effects/<key>.json    메타데이터
```

메타데이터 JSON 예 (`impact_fire`. 규격대로 그렸다면 §4 표의 값을 그대로 옮겨 적으면 된다):

```json
{
  "frameW": 64,
  "frameH": 64,
  "frames": 6,
  "fps": 20,
  "anchor": { "x": 32, "y": 32 },
  "blend": "add",
  "loop": false
}
```

| 필드 | 뜻 |
|---|---|
| `frameW` / `frameH` | 프레임 한 칸의 크기(px). 시트 폭은 `frameW × frames` 여야 한다 |
| `frames` | 프레임 수 (1 이상) |
| `fps` | 초당 프레임. 재생 시간 = `frames ÷ fps` (`fxDurationSec`) |
| `anchor` | 프레임 안의 기준점. 이 점이 맵 좌표에 놓인다 |
| `blend` | `"add"` 또는 `"normal"` |
| `loop` | `true` = 무한 반복, `false` = 한 번 재생하고 사라짐 |

- 프레임 수와 fps 는 키마다 바꿔도 된다. 예를 들어 `impact_fire` 를 8프레임 @24fps 로 바꾸면 재생 시간이 0.333초가 되고 코드는 그대로 따라간다.
  다만 §3 의 **게임 내 실제 재생 시간**보다 길게 만들면 끝까지 보이지 않고 잘린다.
- JSON 이 없거나 깨졌으면 로더는 `FX_DEFAULT_META[key]` 로 읽는다. 일부 필드만 틀렸으면 **그 필드만** 기본값으로 채운다 (`parseFxMeta`).
- 코드 상수는 `FX_ASSET_DIR = 'effects/'`. 실제 URL 은 Vite 의 `import.meta.env.BASE_URL` 이 앞에 붙는다.

## 3. 게임 내 실제 재생 타이밍 (실측 근거)

이펙트 길이는 **게임이 그 이펙트를 화면에 띄워 두는 시간**을 넘으면 안 된다. 아래가 시뮬레이션이 실제로 쓰는 숫자다.
전부 **시뮬레이션 시간** 기준이라 2배속이면 체감은 절반이 되고, 리플레이에서도 같은 프레임이 나온다.

| 상황 | 게임이 주는 시간 | 근거 | 이펙트를 맞추는 법 |
|---|---|---|---|
| 투사체 비행 | **0.25초** (고정) | `PROJECTILE_SEC`. 거리와 무관하게 언제나 0.25초 | `proj_*` 는 반복(loop)이라 길이를 맞출 필요가 없다. 0.25초 안에 4프레임 @12fps = 3프레임만 보이므로 **프레임 하나만 봐도 읽히는 모양**이어야 한다 |
| 광역 예고 | **0.3 ~ 1.5초** (0.3 / 0.8 / 1.0 / 1.2 / 1.3 / 1.4 / 1.5, 압도적 다수가 0.8) | `SHORT_TELEGRAPH_SEC 0.3`, `DEFAULT_TELEGRAPH_SEC 0.8`, 큰 스킬 1.0~1.4(빙하 감옥 1.3 · 대지진 1.4), 눈보라 1.2, 최대 1.5 | `zone_ring_*` / `zone_fill_*` 는 반복이다. 예고 동안 코드가 진행률(0→1)만큼 `zone_fill_*` 을 차오르게 채우고 `zone_ring_*` 테두리를 점점 밝게 한다. 0.3초(=@8fps 로 2프레임)에도 어색하지 않게 |
| 광역 폭발 | **0.25초** | `ZONE_FLASH_SEC`. 예고가 끝난 뒤 impact 표시 | `impact_*` 는 시트 길이와 무관하게 이 0.25초 안에 **한 바퀴 전부** 재생된다 (코드가 진행률에 맞춰 시간을 눌러 준다). 즉 프레임을 늘리면 그만큼 빨리 돈다 |
| 아군 대상 광역 | **0.4초** | `ALLY_AREA_FLASH_SEC` | `heal_burst`(0.333초)가 여기에 들어간다 |
| 장판(linger) | **2 ~ 6초** (대부분 3~5초) | `SkillDef.linger.durationSec` 실제 값 = 2·3·4·5·6 | `zone_fill_*` 반복으로 계속 돈다. 0.5초 한 바퀴가 4~12번 돈다. **시작과 끝이 이어져야** 한다 |
| 눈보라 기믹 | 예고 1.2초 → 장판 3초, 12초 간격(파도마다 −0.5, 최소 4초) | `hazard_blizzard` | `zone_ring_neutral_r**` / `zone_fill_neutral` 을 쓴다 (계열 색 없이 흰·하늘). 반경은 3.5 에서 시작해 파도마다 0.1 씩 자라 5 에서 멈춘다 |
| 장판 반경 | 원형 광역은 **2.5 · 3 · 3.5 · 4 · 4.5 · 5 · 6 유닛 7가지뿐**이다 (가장 흔한 값 3, 그다음 4) | 스킬 `radius` 실제 값 | 그래서 테두리와 내부를 **나눠서** 만든다. 테두리 `zone_ring_*` 은 **그 반경의 크기 그대로** 그린 원 한 장이고, 내부는 `zone_fill_*` 32×32 타일로 채운다. 둘 다 늘리지 않고 1:1 로 그린다 |
| 근접 공격 동작 | **0.333초** | 스프라이트 `attack` 4프레임 @12fps | `slash_*` 0.167초는 공격 동작의 **앞쪽 절반**에 겹친다. 뒤 절반은 자세 복귀라 칼자국이 이미 사라져 있어야 한다 |
| 시전(cast) | 중앙값 **0.45초**, 스킬별 0.4 ~ 1.5초 | 헤드리스 40판 측정. 즉시 시전 스킬도 많다 | `cast_*` 0.40초 한 바퀴가 **한 바퀴 남짓** 돈다. 시작과 끝이 자연스럽게 이어지는 반복이어야 한다 |
| 피격 움찔 | 0.2초 | 스프라이트 `hit` | `impact_*` 가 이 위에 겹친다 |
| 사망 | 0.5초 (그 뒤 마지막 프레임 유지) | 스프라이트 `death` | `death_poof` 0.417초가 그 안에 들어간다 |

### 얼마나 자주 나오는가 (헤드리스 40판, 유닛 1기 기준)

| 이펙트 | 한 판에 재생되는 횟수 | 의미 |
|---|---|---|
| `slash_*` / `proj_*` (기본 공격) | 약 41회 | **가장 많이 보인다.** 1순위 중에서도 먼저 그린다 |
| `impact_*` (피격) | 약 20회 | 스킬 피해가 들어간 지점마다 |
| `cast_*` | 약 5.6회 | 시전 시간이 있는 스킬만 |
| `death_poof` | 0.6회 | 한 판에 한 번 볼까 말까 하지만 가장 눈에 띄는 순간 |

공격 간격 중앙값은 1.2초다 (하위 10% 0.25초, 상위 10% 1.55초). 즉 빠른 유닛은 베기·투사체가 거의 끊기지 않고 이어진다.

## 4. 키 목록 (총 68)

계열(school) 7종 = `fire` · `ice` · `lightning` · `holy` · `nature` · `shadow` · `phys`(무속성·물리).
코드의 `MagicSchool` 에서 `'none'` 이 여기의 `phys` 에 대응한다.

`초` 칸은 `frames ÷ fps` 다. `blend` 의 기본 규칙은 **물리(`phys`)·중립(`neutral`)·연기·먼지는 `normal`, 나머지는 `add`**.

> 📋 **장판 테두리(§4.5) 25종은 게임 데이터에서 자동으로 만들어진다.** 밸런싱으로 스킬 반경이 바뀌면 키 목록도 따라 바뀐다.
> **항상 최신 목록은 `npm run effects:list` 로 확인한다** — 그 출력에 키·크기·프레임·fps·초·blend·loop·anchor·쓰임이 전부 들어 있어
> 이 문서를 보지 않아도 그대로 만들 수 있다. 아래 표는 이 문서를 쓴 시점의 값이다.

### 4.1 A. 피격 폭발 `impact_<school>` — 7종

| 키 | 크기 | 프레임 | fps | 초 | blend | loop | anchor | 쓰임 |
|---|---|---|---|---|---|---|---|---|
| `impact_fire` | 64×64 | 6 | 20 | 0.300 | add | false | (32,32) | 화염 스킬 피해가 들어간 지점 |
| `impact_ice` | 64×64 | 6 | 20 | 0.300 | add | false | (32,32) | 냉기 스킬 피해 |
| `impact_lightning` | 64×64 | 6 | 20 | 0.300 | add | false | (32,32) | 전기 스킬 피해 |
| `impact_holy` | 64×64 | 6 | 20 | 0.300 | add | false | (32,32) | 신성 스킬 피해 |
| `impact_nature` | 64×64 | 6 | 20 | 0.300 | add | false | (32,32) | 자연 스킬 피해 |
| `impact_shadow` | 64×64 | 6 | 20 | 0.300 | add | false | (32,32) | 암흑 스킬 피해 |
| `impact_phys` | 64×64 | 6 | 20 | 0.300 | **normal** | false | (32,32) | 무속성·물리 스킬 피해 |

기존 파티클 `burst` 를 대체한다. **중심 섬광(1~2프레임) → 파편 확산(3~4) → 잔광 소멸(5~6)** 3단 구성으로 그린다.
광역 폭발(0.25초)에서도 프레임이 잘리지 않고 전부 재생되니, 마지막 프레임까지 온전히 그려도 된다 (§3 의 0.25초 참고).

### 4.2 B. 투사체 `proj_*` — 8종

| 키 | 크기 | 프레임 | fps | 초 | blend | loop | anchor | 쓰임 |
|---|---|---|---|---|---|---|---|---|
| `proj_arrow` | 32×32 | 4 | 12 | 0.333 | **normal** | true | (16,16) | 궁수 원거리 기본 공격 |
| `proj_bullet` | 32×32 | 4 | 12 | 0.333 | add | true | (16,16) | 저격수 탄환 (총구 섬광이 빛나므로 가산 합성) |
| `proj_orb_fire` | 32×32 | 4 | 12 | 0.333 | add | true | (16,16) | 화염 투사체 스킬 |
| `proj_orb_ice` | 32×32 | 4 | 12 | 0.333 | add | true | (16,16) | 냉기 투사체 |
| `proj_orb_lightning` | 32×32 | 4 | 12 | 0.333 | add | true | (16,16) | 전기 투사체 |
| `proj_orb_holy` | 32×32 | 4 | 12 | 0.333 | add | true | (16,16) | 신성 투사체 |
| `proj_orb_nature` | 32×32 | 4 | 12 | 0.333 | add | true | (16,16) | 자연 투사체 |
| `proj_orb_shadow` | 32×32 | 4 | 12 | 0.333 | add | true | (16,16) | 암흑 투사체 |

- **오른쪽으로 날아가는 기준**으로 그린다. 코드가 앵커를 축으로 진행 방향만큼 회전시킨다.
- **머리 + 꼬리** 구성. 머리는 오른쪽 끝에 또렷하게, 꼬리는 왼쪽으로 옅어진다.
- 비행 시간 0.25초 안에 3프레임 정도만 보인다. 프레임 사이 차이는 꼬리의 흔들림 정도로 작게 두고, **한 프레임만 봐도 화살·탄환·마력구가 구분**되게 한다.
- `proj_orb_phys` 는 없다. 무속성 투사체는 `proj_bullet` 을 쓴다.

### 4.4 D. 근접 베기 `slash_*` — 3종

| 키 | 크기 | 프레임 | fps | 초 | blend | loop | anchor | 쓰임 |
|---|---|---|---|---|---|---|---|---|
| `slash_light` | 64×64 | 4 | 24 | 0.167 | **normal** | false | **(16,32)** | 빠른 한 손 무기 (검사·암살자) |
| `slash_heavy` | 64×64 | 4 | 24 | 0.167 | **normal** | false | **(16,32)** | 양손 큰 동작 (버서커·대검사) |
| `slash_pierce` | 64×64 | 4 | 24 | 0.167 | **normal** | false | **(16,32)** | 찌르기 (창·단검) |

- **호를 그리는 칼자국**. 프레임마다 호가 진행해 한 번 휘두른 궤적이 읽혀야 한다. 마지막 프레임은 옅은 잔상만 남긴다.

  왼쪽 공격은 180° 회전이라 위아래까지 같이 뒤집히므로, 호는 **위아래 대칭**에 가깝게 그려야 방향에 상관없이 자연스럽다.
- `slash_light` 는 얇고 빠른 한 줄, `slash_heavy` 는 두껍고 넓은 반원, `slash_pierce` 는 앞으로 뻗는 쐐기.
- 공격 동작 0.333초의 **앞쪽 절반**만 쓴다. 0.167초를 넘기게 그리면 자세가 이미 돌아온 뒤에도 칼자국이 남아 어색하다.

### 4.5 E. 장판·예고 `zone_ring_*` / `zone_fill_*` — 33종

**테두리와 내부를 나눠서** 만든다.
테두리는 **반경마다 그 크기 그대로 그린 원 한 장**이고, 내부는 32×32 타일을 이어 붙여 채운다. 둘 다 **늘리지 않는다**.

#### 테두리 `zone_ring_<계열>_r<반경×10>` (25종) — 반경마다 원본, 4프레임 @8fps, 0.500초, loop true

**원칙: 늘리거나 이어 붙이지 않는다. 그 크기로 딱 맞게 그린다.**
필요한 크기가 7가지로 정해져 있으니 그 크기로 바로 만든다. 그래야 가장 예쁘게 나온다.

- (지난 방식 1) 64×64 원 한 장을 반경에 맞춰 2~5배로 늘리기 → 배율이 3.5 같은 비정수가 되어 한 픽셀이 3칸·4칸으로 들쭉날쭉했다.
- (지난 방식 2) 32×32 조각을 둘레에 반복 → 픽셀 밀도는 1:1 이지만 **원 전체의 형태를 작가가 통제할 수 없다.**
- (지금) 반경별 원본 → 배율 1:1 이라 1 px 선도 또렷하고, 원 한 장을 작가가 끝까지 통제한다.

**키 이름 규칙** — `zone_ring_<계열>_r<반경×10>`

| 예 | 뜻 |
|---|---|
| `zone_ring_fire_r35` | 화염, 반경 **3.5** 유닛 |
| `zone_ring_phys_r60` | 무속성·물리, 반경 **6** 유닛 |
| `zone_ring_neutral_r45` | 맵 기믹(눈보라), 반경 **4.5** 유닛 |

반경 숫자는 **×10 한 정수**다 (3 → `r30`, 4.5 → `r45`). 계열은 7종 + `neutral`.

**크기 표** — 프레임 한 변 = `반경 × 2 × 32 px` (정사각형). 시트 폭 = 한 변 × 4프레임.

| 반경(유닛) | 태그 | 프레임 크기 | 시트 크기 (4프레임) | anchor (프레임 중앙) |
|---|---|---|---|---|
| 2.5 | `r25` | 160×160 | 640×160 | (80,80) |
| 3 | `r30` | 192×192 | 768×192 | (96,96) |
| 3.5 | `r35` | 224×224 | 896×224 | (112,112) |
| 4 | `r40` | 256×256 | 1024×256 | (128,128) |
| 4.5 | `r45` | 288×288 | 1152×288 | (144,144) |
| 5 | `r50` | 320×320 | 1280×320 | (160,160) |
| 6 | `r60` | 384×384 | 1536×384 | (192,192) |

**배치** — 원의 **중심이 프레임 정중앙**(= anchor)이고, **테두리가 프레임 가장자리에 닿는다.**
반경 3.5 = 224×224 프레임이면 중심 (112,112), 선은 그 중심에서 112 px 떨어진 자리 = 프레임의 상하좌우 끝 변에 스친다.
코드는 이 원을 **회전시키지 않고 배율 1 로 그대로** 얹는다. 앵커가 장판의 중심 좌표에 놓인다.

```
  zone_ring_fire_r35 한 프레임 (224×224 = 맵 7 유닛)
  (0,0) ┌───────────────●───────────────┐  ← y=0 에서 테두리가 프레임 위 변에 닿는다
        │          ∙∙        ∙∙          │
        │       ∙                  ∙     │
        │     ∙        (안쪽은           ∙│
        ●    ∙       zone_fill 타일이     ∙●  ← x=223 에서 오른쪽 변에 닿는다
        │     ∙         채운다)          ∙│
        │       ∙                  ∙     │
        │          ∙∙        ∙∙          │
        └───────────────●───────────────┘ (223,223)
                  중심 = anchor (112,112) = 장판의 중심 좌표
                  중심에서 선까지 = 112 px = 3.5 유닛 = 그 스킬의 반경
```

**실제로 필요한 조합 25종** (게임 데이터에서 자동 생성 — 스킬 21조합 + 눈보라 4)

| 계열 | 반경 | 키 | 쓰는 스킬 |
|---|---|---|---|
| `fire` | 3 / 3.5 / 4 | `zone_ring_fire_r30` `_r35` `_r40` | 화염 폭풍·지옥불 / 화염 비·메테오 / 유성 낙하 |
| `ice` | 3 / 3.5 / 4 / 4.5 | `zone_ring_ice_r30` `_r35` `_r40` `_r45` | 빙결 파동 / 서리 숨결 / 블리자드 / 빙하 감옥 |
| `lightning` | 3 / 4 | `zone_ring_lightning_r30` `_r40` | 뇌전 장막 / 뇌우 |
| `holy` | 3 / 4 | `zone_ring_holy_r30` `_r40` | 심판의 빛 / 광역 치유·보호 결계·결계 강화 |
| `nature` | 2.5 / 3 | `zone_ring_nature_r25` `_r30` | 독포자 / 가시 덩굴·정령 폭발 |
| `shadow` | 3 / 5 | `zone_ring_shadow_r30` `_r50` | 비탄의 울음·저주 / 암흑 축복·어둠의 의식 |
| `phys` | 2.5 / 3 / 3.5 / 4 / 5 / 6 | `zone_ring_phys_r25` `_r30` `_r35` `_r40` `_r50` `_r60` | 연막 단검·폭발탄 등 / 대지 강타·다중 사격 등 / 화살비·비전 폭풍 / 점액 파도·방벽 등 / 대지진·도발의 포효 / 전투 함성·용의 포효 등 |
| `neutral` | 3.5 / 4 / 4.5 / 5 | `zone_ring_neutral_r35` `_r40` `_r45` `_r50` | 빙하 눈보라 (파도마다 반경이 0.1 씩 자라 3.5 → 5) |

> ⚠ 이 목록은 **밸런싱으로 스킬 반경이 바뀌면 같이 바뀐다.** 위 표는 문서를 쓴 시점의 값이고,
> **항상 최신 목록은 `npm run effects:list`** 다. 코드는 `src/core/data/skills.ts` 의 `SKILLS`(대상이 `enemy_area`·`ally_area` 이고
> `radius` 가 있는 스킬)와 `src/core/data/maps.ts` 의 `hazards` 에서 조합을 모아 `FX_RING_KEYS` 를 만든다.

**그리는 법**

- **선 굵기는 반경과 무관하게 1~2 px.** 반경이 커지면 **선이 길어질 뿐** 굵어지지 않는다.
  배율 1:1 이라 캐릭터 스프라이트와 픽셀 크기가 같다 — 1 px 선도 또렷하게 보인다.
- **안쪽을 꽉 채우지 않는다.** 내부는 `zone_fill_*` 가 채운다. 테두리는 원주 부근(바깥 10 px 안쪽)만 쓴다.
  큰 키(384×384 × 4프레임 = 1536×384)도 실제로 칠하는 픽셀은 원주뿐이라 몇 %밖에 안 된다.
- 가장 밝은 선은 **끊기지 않고 닫힌 원**이어야 한다. 그 안쪽으로 짧은 눈금이나 점선을 더하면 계열감이 산다.
- 4프레임은 **고리가 도는 느낌**으로 만든다 (점선이 원주를 따라 조금씩 회전). 마지막 프레임 → 첫 프레임이 끊기지 않아야 한다.
  0.3초짜리 짧은 예고(= @8fps 로 2프레임)에서도 어색하지 않게.
- **이음매 검사는 없다.** 이어 붙이는 타일이 아니므로 `npm run effects:check` 는 대신 **크기**를 본다
  (프레임 한 변 = 반경 × 64, 시트 폭 = 한 변 × 프레임 수).

#### 내부 타일 `zone_fill_*` (8종) — 32×32, 4프레임 @8fps, 0.500초, loop true

| 키 | blend | anchor | 쓰임 |
|---|---|---|---|
| `zone_fill_fire` | add | **(0,0)** | 화염 장판 내부 |
| `zone_fill_ice` | add | **(0,0)** | 냉기 |
| `zone_fill_lightning` | add | **(0,0)** | 전기 |
| `zone_fill_holy` | add | **(0,0)** | 신성 |
| `zone_fill_nature` | add | **(0,0)** | 자연 |
| `zone_fill_shadow` | add | **(0,0)** | 암흑 |
| `zone_fill_phys` | **normal** | **(0,0)** | 무속성·물리 |
| `zone_fill_neutral` | **normal** | **(0,0)** | 맵 기믹 (눈보라) |

- **상하좌우로 이어 붙여도 이음매가 보이지 않는 타일**이어야 한다. 원 내부를 이 타일로 바둑판처럼 채운다.
- 이음매 규칙: 오른쪽 끝 열(x=31)의 다음 픽셀은 왼쪽 첫 열(x=0)이다. 아래 끝 행(y=31)의 다음은 위 첫 행(y=0)이다.
  경계를 넘는 무늬는 **반대쪽에서 이어서** 그려야 한다. `npm run effects:check` 가 이 연속성을 검사한다.
- 전면을 꽉 채우지 말고 **성기게** (덮인 면적 30~60%) 그린다. 그 아래의 지형과 유닛 발이 비쳐 보여야 한다.
- 모든 프레임이 같은 타일 규격이다. 프레임 사이에는 무늬가 **흘러가는** 느낌(불길이 일렁이거나 서리가 번지는)만 준다.

  - `status_freeze` / `status_shield` 는 **발밑**, 유닛 **아래**에 깔린다. 가운데는 유닛에 가려지니 바깥쪽 형태로 읽히게 그린다.

## 6. 제작 우선순위

1순위부터 넣으면 그 키만 제작 에셋으로 바뀌고 나머지는 임시 이펙트가 계속 나온다. **단계별로 나눠 넣어도 된다.**

### 1순위 — 21종 (가장 자주 보인다)

| 묶음 | 키 |
|---|---|
| 피격 폭발 7 | `impact_fire` `impact_ice` `impact_lightning` `impact_holy` `impact_nature` `impact_shadow` `impact_phys` |
| 투사체 8 | `proj_arrow` `proj_bullet` `proj_orb_fire` `proj_orb_ice` `proj_orb_lightning` `proj_orb_holy` `proj_orb_nature` `proj_orb_shadow` |
| 베기 3 | `slash_light` `slash_heavy` `slash_pierce` |
| 단발 3 | `heal_burst` `death_poof` `crit_star` |

기본 공격(베기·투사체)이 한 판에 유닛당 40회 넘게 나온다. 이 21종만 넣어도 화면 인상이 크게 바뀐다.

### 2순위 — 40종 (광역기 연출)

| 묶음 | 키 |
|---|---|
| 시전 7 | `cast_fire` `cast_ice` `cast_lightning` `cast_holy` `cast_nature` `cast_shadow` `cast_phys` |
| 장판 테두리 25 | `zone_ring_<계열>_r<반경×10>` — §4.5 의 조합 표 (계열마다 반경이 2~6가지) |
| 장판 내부 8 | `zone_fill_*` 7계열 + `zone_fill_neutral` |

- `zone_ring` 과 `zone_fill` 은 **같은 계열끼리 짝으로** 넣어야 한 덩어리로 보인다.
- 테두리 25종은 **계열 안에서 반경만 다른 같은 그림**이다. 한 계열의 원 하나를 정하면 나머지 반경은 그 규칙대로 크기만 바꿔 그리면 된다.
  반경이 흔한 순서(`r30` → `r40` → `r35` → `r25` → `r45` → `r50` → `r60`)로 넣으면 화면에서 먼저 눈에 띈다.
- 테두리 개수는 게임 데이터에 달렸다. **넣기 전에 `npm run effects:list` 로 현재 목록을 확인한다.**

### 3순위 — 7종 (있으면 좋은 것)

`status_stun` `status_burn` `status_freeze` `status_shield` `buff_ring` `dodge_puff` `summon_circle`

## 7. 픽셀 규칙

스프라이트와 같다 ([SPRITES.md](SPRITES.md)).

- **정수 픽셀.** 픽셀 격자에 딱 맞게 찍는다. 부드러운 곡선을 만들려고 반픽셀을 쓰지 않는다.
- **안티앨리어싱·블러 금지.** 알파는 **0 또는 255 만** 쓴다. 반투명 픽셀이 하나라도 있으면 검사기가 실패한다.
  옅게 보이게 하려면 알파를 낮추지 말고 **어두운/성긴 색 픽셀**로 표현한다 (디더링은 써도 된다).
- **투명 PNG.** 배경은 완전 투명. 검은 배경 위에 그리고 검정을 남기면 `add` 합성에서는 티가 안 나지만 `normal` 에서는 사각형이 그대로 보인다.
- **타일 이음매**: `zone_fill_*` 만 좌우·상하가 이어져야 한다. `zone_ring_*` 은 이어 붙이지 않는 원 한 장이라 이음매가 없다 (대신 **크기**가 규격이다). §4.5 참고.
- 화면에서는 캐릭터가 화면 폭의 약 1/14 로 축소된다. **실루엣이 단순**해야 읽힌다. 1 px 점 몇 개만으로 된 이펙트는 보이지 않는다.
- `add` 합성은 밝은 색이 배경과 더해져 **더 밝아진다.** 어두운 색은 거의 사라진다. 그래서 `add` 키는 가장자리를 검게 두르지 말고 **중심을 가장 밝게** 잡는다.
- `normal` 합성은 그린 그대로 덮는다. 외곽선을 넣어 실루엣을 잡아도 된다.

## 8. 폴백 규칙

1. 전투 시작 시 `preloadFx(FX_KEYS)` 로 68개 키의 `public/effects/<key>.png` · `.json` 을 한 번 로드한다 (키 수는 스킬 반경에 따라 달라진다 — `npm run effects:list`).
2. PNG 가 있으면 그것을 쓴다. JSON 이 없거나 깨졌으면 `FX_DEFAULT_META[key]` 로 읽는다 (필드 단위로 채운다).
3. PNG 가 없거나(404) 로드에 실패하면 **코드 생성 임시 이펙트**를 쓴다. 조용히 폴백하고 에러로 멈추지 않는다.
4. 목록에 없는 키는 아예 로드하지 않는다 (런타임은 조용히 무시한다). 다만 **검사기는 오류로 잡는다** — `public/effects/` 에 `FX_KEYS` 밖 키의 `.png` / `.json` 이 있으면 `npm run effects:check` 가 실패한다. 하위 폴더와 `.png` / `.json` 이 아닌 파일만 경고로 넘어간다.
5. 로드는 비동기다. 끝나기 전 프레임은 임시 이펙트로 그리고, 끝나면 다음 프레임부터 바꿔 그린다. **시뮬레이션에는 영향이 없다.**
6. DOM 이 없는 환경(node 헤드리스)에서는 항상 임시 이펙트를 쓴다.
7. 일부 키만 넣어도 된다. 넣은 키만 제작 에셋으로 바뀐다.

## 9. 제작 전·후 확인 방법

### 만들기 전 — 무엇을 만들어야 하는지

```
npm run effects:list
```

필요한 키 전부를 **키 · 프레임 크기 · 시트 크기 · 프레임 수 · fps · 재생 시간 · blend · loop · anchor · 쓰임** 표로 출력한다.
값은 코드(`FX_KEYS` · `FX_DEFAULT_META`)에서 그대로 읽으므로 **이 출력이 언제나 정답**이다.
장판 테두리처럼 게임 데이터(스킬 반경)에서 자동으로 만들어지는 키는 밸런싱 때마다 바뀌니, 작업 시작 전에 한 번 돌려 본다.
`.json` 에 적을 값도 이 표에서 그대로 옮기면 된다.

| 옵션 | 쓰임 |
|---|---|
| (없음) | 표로 출력 |
| `-- --keys` | 키 이름만 한 줄에 하나씩 (스크립트용) |
| `-- --json` | JSON 배열 (도구용) |

### 만든 뒤 — 규격에 맞는지

```
npm run effects:check
```

`public/effects/` 안의 파일을 검사한다.

| 검사 | 실패하면 |
|---|---|
| 키 이름이 `FX_KEYS` 에 있는가 | 오류. 오타이거나 목록에 없는 키다 |
| PNG 크기 = `frameW × frames` × `frameH` | 오류. 프레임 수·프레임 크기 또는 시트 크기가 틀렸다 |
| JSON 필드(`frameW` `frameH` `frames` `fps` `anchor` `blend` `loop`)가 모두 있고 타입이 맞는가 | 오류 |
| `blend` 가 `"normal"` / `"add"` 인가, `anchor` 가 프레임 안인가 | 오류 |
| 알파가 0 또는 255 인가 | 오류. 반투명 픽셀 위치를 알려준다 |
| `zone_fill_*` 의 좌우·상하 이음매가 이어지는가 | 오류. 어느 방향이 끊겼는지 알려준다 |
| `zone_ring_*` 의 **크기** — 프레임 한 변 = 반경 × 64 (정사각형), 시트 폭 = 한 변 × 프레임 수 | 오류. 테두리는 이어 붙이지 않으므로 이음매 대신 크기를 본다 |
| JSON 값이 §4 표(기본값)와 다른가 | 경고만. 의도한 것이면 그대로 두면 된다 |
| PNG 는 있는데 JSON 이 없는가 | 경고. 기본 메타로 읽힌다 |
| JSON 은 있는데 PNG 가 없는가 | **오류**. JSON 만 있으면 그 키는 임시 이펙트로 남는다. PNG 를 넣거나 JSON 을 빼라 |

- `public/effects/` 가 비어 있으면 **"아직 제작 에셋 없음 (임시 이펙트 사용 중)"** 으로 통과한다.
- 오류가 하나라도 있으면 종료 코드 1 이다.

화면에서 직접 보려면 `npm run dev` 로 띄우고 도트 모드(기본)로 전투를 관전한다. 파일을 바꾸면 새로고침해야 다시 로드된다.

## 10. 렌더 파이프라인 요약 (작가 참고)

- 1 맵 유닛 = 32 px 인 오프스크린 캔버스(992×736)에 **지형 타일 → 장판·예고 → 유닛(y 오름차순) → 이펙트** 순으로 그린 뒤 화면 캔버스로 확대한다. `imageSmoothingEnabled = false`.
- **이펙트 시트는 늘려 그리지 않는다** (1:1). 장판 테두리도 그 반경의 크기로 만든 원 한 장을 **배율 1 로 한 번** 얹는다 (영역당 draw 1회).
  정확히 맞는 키가 없을 때만 같은 계열에서 반경이 가장 가까운 키를 쓰고, 그 배율이 0.9~1.1 을 벗어나면 시트를 쓰지 않고 벡터 테두리로 폴백한다.
  (실제로 광역 스킬은 전부 배율 1 이고, 반경이 0.1 씩 자라는 눈보라만 최대 6% 정도 어긋난다.)
  선분(line) 모양 영역은 시트를 쓰지 않고 예전처럼 벡터 테두리로 그린다.
- 유닛보다 **아래**에 깔리는 것: `zone_ring_*` · `zone_fill_*` (지형 바로 위) 와 `cast_*` · `status_freeze` · `status_shield` · `buff_ring` (유닛 발밑). 가운데가 유닛 실루엣에 가려지므로 **바깥쪽 형태**로 읽히게 그린다.
- 유닛보다 **위**에 얹히는 것: 나머지 전부 — `impact_*` · `proj_*` · `slash_*` · `heal_burst` · `crit_star` · `dodge_puff` · `death_poof` · `summon_circle`, 그리고 머리 위의 `status_stun` · `status_burn`.
- 모든 이펙트 타이밍은 `frame.timeSec`(시뮬레이션 시간) 기준이다. 배속을 올리면 그만큼 빨리 돌고, 리플레이에서도 같은 프레임이 나온다.
- HP 바·이름·상태 점·말풍선·회피 텍스트·피해 숫자는 화면 캔버스에 **벡터**로 얹는다. 이펙트 시트에 글자를 넣지 않는다.
- 간단 모드(`RenderMode 'simple'`)는 이펙트 시트를 쓰지 않는다.
