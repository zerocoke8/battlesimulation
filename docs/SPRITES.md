# 도트 스프라이트 에셋 규격 (v0.7)

전투 관전 화면의 **도트 모드**(기본)가 쓰는 캐릭터 스프라이트 규격. 작가는 이 문서만 보고 그대로 그릴 수 있어야 한다.
코드 계약은 `src/ui/pixel/spriteTypes.ts` (`SpriteMeta`, `DEFAULT_META`, `spriteKeyForUnit`) 에 있고, 이 문서와 항상 일치해야 한다.

## 1. 프레임과 시트

| 항목 | 값 |
|---|---|
| 프레임 크기 | **64 × 64 px** (투명 PNG) |
| 시트 구성 | **애니메이션당 1행**, 열 = 프레임. 행 순서는 아래 표의 순서 (idle → death) |
| 시트 폭 | 가장 긴 애니메이션(walk 6프레임) 기준 **384 px**. 짧은 행의 남는 칸은 비워 둔다 |
| 시트 높이 | 6행 × 64 = **384 px** |
| 방향 | **오른쪽을 보는 기준**으로 그린다. 왼쪽을 볼 때는 코드가 좌우 반전한다 (왼쪽용 프레임을 따로 그리지 않는다) |
| 앵커(발 위치) | 프레임 안 **(32, 58)**. 이 점이 유닛의 맵 좌표에 놓인다. 발바닥이 y=58 에 닿게 그린다 |
| 화면 크기 | 64 px = 맵 **2 유닛**. 오프스크린 캔버스는 1 유닛 = 32 px 이므로 원본 크기 그대로 찍힌다 |
| 외곽선 | 1 px 짙은 외곽선 권장 (배경 타일 위에서 실루엣이 읽히도록). 400 px 폭 화면에서는 캐릭터가 화면 폭의 약 1/14 로 축소되므로 실루엣이 단순해야 한다 |
| 팔레트 | 제한 없음. 단 직업 시트는 §4 의 틴트 규칙 때문에 **주요 색 영역(옷·망토)** 을 채도 있는 한 계열로 칠한다 |

## 2. 애니메이션 6종 (확정)

| 이름 | 행 | 프레임 | fps | 재생 | 언제 |
|---|---|---|---|---|---|
| `idle` | 0 | 4 | 6 | 반복 | 정지 상태. 숨쉬기·무기 흔들림 정도의 작은 변화 |
| `walk` | 1 | 6 | 10 | 반복 | 이전 프레임 대비 위치가 바뀌었을 때 |
| `attack` | 2 | 4 | 12 | 1회 | `attack`/`skill` 이벤트의 시전자였을 때. 유지 시간 = 프레임 수 ÷ fps (기본 4 ÷ 12 ≈ 0.33초) 라 4프레임 전부 한 번 보인다 (근접 베기·활 당기기·총 발사·지팡이 휘두르기) |
| `cast` | 3 | 4 | 8 | 반복 | `casting` 이 있는 동안 (팔을 들고 마력이 모이는 동작) |
| `hit` | 4 | 2 | 10 | 1회 | 피격(`attack.to`) 순간. 코드가 흰 깜빡임을 겹친다 |
| `death` | 5 | 4 | 8 | 1회, 마지막 유지 | `alive` 가 false 가 된 뒤. 마지막 프레임은 쓰러진 모습. 코드가 반투명으로 유지한다 |

- 프레임 사이 차이가 **눈에 보여야** 한다: 팔·다리·무기 위치가 프레임마다 달라야 한다. 색만 바뀌는 프레임은 안 된다.
- 애니메이션 시간은 시뮬레이션 시간 기준이다. 배속을 올리면 그만큼 빨리 돌고, 리플레이에서도 같은 프레임이 나온다.
- 1회 재생(attack / hit / death)은 끝나면 마지막 프레임에서 멈춘다. attack·hit 은 프레임 수 ÷ fps 만큼 유지된 뒤(JSON 의 frames·fps 를 바꾸면 그에 맞춰) idle/walk 로 돌아간다.

## 2.1 동작별 정확한 초수와 실제 재생 빈도 (실측)

한 번 재생에 걸리는 시간은 **프레임 수 ÷ fps** 로 정해진다. 아래가 기본 규격의 확정값이다.

| 동작 | 프레임 × fps | 1회 재생 시간 | 재생 방식 | 한 프레임이 화면에 머무는 시간 |
|---|---|---|---|---|
| `idle` | 4 × 6fps | 0.667초 (한 바퀴) | 무한 반복 | 0.167초 |
| `walk` | 6 × 10fps | 0.600초 (한 바퀴) | 무한 반복 | 0.100초 |
| `attack` | 4 × 12fps | **0.333초** | 1회, 끝나면 idle/walk 로 | 0.083초 |
| `cast` | 4 × 8fps | 0.500초 (한 바퀴) | 시전이 끝날 때까지 반복 | 0.125초 |
| `hit` | 2 × 10fps | **0.200초** | 1회 | 0.100초 |
| `death` | 4 × 8fps | **0.500초** | 1회, 마지막 프레임 유지 | 0.125초 |

- 이 초수는 **시뮬레이션 시간** 기준이다. 2배속이면 실제 체감은 절반이 된다.
- `attack` 과 `hit` 은 1회 재생 시간이 끝나면 곧바로 이전 상태로 돌아간다. 즉 **공격 동작은 반드시 0.333초 안에 완결**되어야 한다. 0.333초를 넘겨 이어지는 동작(예: 크게 휘두른 뒤 자세 복귀)은 잘린다.
- `death` 는 0.5초 재생 후 마지막 프레임이 계속 남는다. 마지막 프레임은 **바닥에 쓰러진 정지 그림**이어야 한다. 코드가 반투명으로 낮춘다.
- 프레임 수와 fps 는 캐릭터별 JSON 으로 바꿀 수 있다 (§3). 보스 `idle` 을 6프레임으로 늘리는 식. 바꾸면 위 초수도 그에 맞춰 자동으로 달라진다.

### 실제 전투에서의 재생 비중 (헤드리스 40판 측정)

살아있는 동안의 시간을 100% 로 봤을 때의 비중이다. 어떤 동작에 공을 들여야 하는지 판단하는 기준으로 쓴다.

| 동작 | 10일차 비중 | 1일차 비중 | 전투 한 판에서 유닛 1기가 재생하는 횟수 (10일차) |
|---|---|---|---|
| `idle` | 35.9% | 40.8% | 42.5회 |
| `attack` | 29.3% | 24.5% | 41.6회 |
| `walk` | 21.0% | 24.9% | 24.6회 |
| `hit` | 8.1% | 7.7% | 20.3회 |
| `cast` | 5.6% | 2.0% | 5.6회 |
| `death` | — (죽은 뒤 계속 유지) | — | 0.6회 |

- **`idle` 과 `attack` 이 화면 시간의 3분의 2** 를 차지한다. 이 둘을 가장 공들여 그린다.
- 공격 간격 중앙값은 1.2초다 (하위 10% 0.25초, 상위 10% 1.55초). 즉 공격 동작 0.333초가 끝나면 보통 0.9초 정도 idle 이나 walk 로 돌아간다. 빠른 유닛은 공격 동작이 거의 끊기지 않고 이어진다.
- 시전 지속은 중앙값 0.45초다 (스킬별 시전 시간 0.4~1.5초, 즉시 시전 스킬도 많다). `cast` 한 바퀴가 0.5초이므로 **대개 한 바퀴 남짓 돌고 끝난다.** 시작과 끝이 자연스럽게 이어지는 반복 동작이어야 한다.
- `hit` 은 한 판에 20회 넘게 나온다. 짧지만 눈에 띄는 움찔거림이 필요하다.

### 동작 우선순위 (코드가 고르는 순서)

한 순간에 하나만 재생된다. 위에서부터 먼저 잡힌 것이 이긴다.

1. `death` — 죽었을 때 (그 뒤로는 계속)
2. `cast` — 시전 중일 때
3. `attack` — 마지막 공격·스킬로부터 0.333초 이내
4. `hit` — 마지막 피격으로부터 0.2초 이내
5. `walk` — 직전 프레임보다 위치가 움직였을 때
6. `idle` — 그 외

즉 **시전 중에는 피격 동작이 나오지 않고, 공격 직후 0.333초 동안은 피격 동작이 묻힌다.** 공격 동작 안에 살짝 움츠리는 느낌을 넣어두면 그 구간이 덜 뻣뻣하다.

## 3. 파일과 메타데이터

```
public/sprites/<key>.png     시트 이미지
public/sprites/<key>.json    메타데이터
```

메타데이터 JSON 예 (`DEFAULT_META` 와 같은 값. 규격대로 그렸다면 이 파일을 그대로 복사하면 된다):

```json
{
  "frameW": 64,
  "frameH": 64,
  "anchor": { "x": 32, "y": 58 },
  "anims": {
    "idle":   { "row": 0, "frames": 4, "fps": 6,  "loop": true },
    "walk":   { "row": 1, "frames": 6, "fps": 10, "loop": true },
    "attack": { "row": 2, "frames": 4, "fps": 12, "loop": false },
    "cast":   { "row": 3, "frames": 4, "fps": 8,  "loop": true },
    "hit":    { "row": 4, "frames": 2, "fps": 10, "loop": false },
    "death":  { "row": 5, "frames": 4, "fps": 8,  "loop": false }
  }
}
```

- `row` / `frames` / `fps` / `loop` 는 애니메이션마다 바꿔도 된다 (예: 보스 idle 을 6프레임으로). 행 순서를 바꾸면 `row` 를 그에 맞춘다.
- JSON 이 없거나 깨졌으면 로더는 `DEFAULT_META` 로 읽는다. 어떤 애니메이션이 빠져 있으면 그 항목만 기본값으로 채운다 (`parseSpriteMeta`).
- 프레임 크기를 64 가 아닌 값으로 정하면 `frameW`/`frameH`/`anchor` 를 반드시 적는다. 화면 크기는 프레임 폭 32 px 당 1 유닛으로 환산한다.

## 5. 팔레트 틴트 (세부 직업·팀 색)

- 직업 시트(`tintable: true`)에만 적용한다. 몬스터·소환물 시트는 틴트하지 않는다.
- 코드는 시트의 **채도 있는 픽셀**(HSL 채도 ≥ 0.35, 명도 0.2~0.85)의 색상(hue)만 세부 직업 색으로 돌리고 명도·채도는 유지한다. 피부색·금속색·외곽선은 채도가 낮게 칠해 틴트에서 빠지게 한다.
- 세부 직업 색 (수치는 코드 `src/ui/pixel/*` 에 상수로 있으며 이 문서의 색은 참고용):

| 메인 | 세부 1 | 세부 2 | 세부 3 |
|---|---|---|---|
| 마법사 | 화염 — 주황·빨강 | 전기 — 노랑·보라 | 냉기 — 하늘·흰색 |
| 검사 | 대검사 — 진홍 | 쾌검사 — 청록 | 마검사 — 보라 |
| 그 외 직업 | 세부 직업 순서대로 빨강 / 초록 / 파랑 계열 |

- 팀 구분(A/B)은 스프라이트 색이 아니라 **발밑 원·HP 바·이름표 색**으로 한다. 시트를 팀별로 두 벌 만들지 않는다.
- 분화 전 캐릭터는 시트 원본 색 그대로.

## 6. 폴백 규칙

1. 렌더러는 전투 시작 시 유닛들의 키를 모아 `public/sprites/<key>.png` 와 `.json` 을 로드한다.
2. PNG 가 있으면 그것을 쓴다. JSON 이 없거나 깨졌으면 `DEFAULT_META` 로 읽는다.
3. PNG 가 없거나(404) 로드에 실패하면 **코드 생성 임시 스프라이트**(`src/ui/pixel/` 의 생성기)를 쓴다. 임시 스프라이트도 같은 64×64 · 6행 규격이며 직업 9종·몬스터 18종·소환물 4종의 형태가 서로 다르다.
4. 알 수 없는 키(목록에 없는 값)는 `FALLBACK_SPRITE_KEY`(검사) 임시 스프라이트로 그린다. 에러로 멈추지 않는다.
5. 에셋 로드는 비동기다. 로드가 끝나기 전 프레임은 임시 스프라이트로 그리고, 끝나면 다음 프레임부터 바꿔 그린다. 시뮬레이션에는 영향이 없다.

## 7. 렌더 파이프라인 요약 (작가 참고)

- 1 맵 유닛 = 32 px 인 오프스크린 캔버스에 지형 타일 → 장판·예고 → 유닛(y 오름차순) → 이펙트 순으로 그린 뒤, 화면 캔버스로 확대·축소한다. `imageSmoothingEnabled = false`.
  배율은 정수로 내려도 캔버스의 90% 이상을 채울 때만 **정수 배율**(픽셀 완전 정렬)을 쓰고, 그 밖(DPR 1.25~1.75 등)에서는 소수 배율로 최근접 보간해 간단 모드와 같은 크기로 맵 전체를 채운다 (검은 띠 없음).
- 맵 28×20 유닛 + 사방 1.5 유닛 여백 = 31×23 유닛 = 오프스크린 992×736 px.
- HP 바·이름·상태 점·말풍선·회피 텍스트·피해 숫자·붕괴 배너는 화면 캔버스에 벡터로 얹는다 (픽셀 시트에 넣지 않는다).
