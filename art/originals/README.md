# art/originals — 그림 원본 보관소

`public/` 에 배포되는 그림의 **줄이기 전 원본**이다. 여기 있는 파일은 빌드에 들어가지 않는다
(`vite` 는 `public/` 만 `dist/` 로 복사한다).

`public` 에는 표시 크기에 맞춘 그림을 두고, 원본은 여기 두고, `npm run art:optimize` 로 둘을 잇는다.

## 들어 있는 것

| 폴더 | 원본 크기 | public 목표 | 왜 그 크기·형식인가 |
|---|---|---|---|
| `backgrounds/` | 1484×1060 RGB · 4장 | 896×640 **RGB**(colortype 2) | 맵 28×20 유닛 × 32px — `src/ui/pixel/terrain.ts` 가 맵 내부에 그리는 크기. 맵을 빈틈없이 덮으므로 알파 불필요 |
| `icons/` | 1254×1254 RGBA · 9장 | 256×256 **RGBA**(colortype 6) | `src/ui/pixel/icons.ts` 가 여백을 잘라 128×128 캔버스에 담아 최대 20px 배지로 그린다. 여백 판정이 알파를 본다 |

파일 이름은 `public/` 쪽과 같다 (`art/originals/<하위폴더>/<파일명>`).

## 쓰는 법

```
npm run art:optimize            # 원본 → public 에 표시 크기로 다시 생성
npm run art:optimize -- --check # 파일을 쓰지 않고 현재·목표 크기와 절감량만 확인
```

- 도구는 **항상 이 폴더의 원본을 입력으로** 쓴다. `public/` 의 이미 줄인 파일을 또 줄여 화질이 깎이는 일이 없고,
  몇 번을 돌려도 결과가 바이트 단위로 같다.
- 여기에 원본이 아직 없으면 도구가 `public/` 의 파일을 **먼저 여기로 복사한 뒤** 줄인다 (첫 실행 1회).
- 그림을 새로 그리면 `public/` 이 아니라 **여기에** 큰 원본을 넣고 도구를 돌린다.
- 목표 크기·색 타입 표는 `tools/optimize-art.ts` 안에 있다. 렌더러의 표시 크기를 바꿨다면 그 표도 같이 고친다.
- `colorType: 2`(RGB) 로 지정한 폴더에 알파가 255 아닌 픽셀이 있는 그림을 넣으면, 도구가 투명도를 소리 없이 버리는 대신
  그 픽셀 좌표를 찍고 오류로 멈춘다.
